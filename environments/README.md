# 环境与执行边界

## 无模型检查

`tools/validate_handoff.py` 与 `tools/reproduce_latest_scores.py` 只使用Python标准库，不调用模型、网络或浏览器。前者检查140对任务与资产、隔离输入和核心来源摘要；后者读取Release分包里的原结果及原标签重新计数。

## 原实验环境

- 本机静态处理/测试：Python3.9.13；`research/competing_rules_20260923/requirements.txt` 是此前实际环境的依赖记录。
- 网页runner：原服务器Python3.10环境，依赖requests、Flask、浏览器自动化等；依各具体入口和已归档测试配置。不要将旧Windows与Linux环境简单合并为一个可保证安装的lock。
- Qwen3.8-27B服务：Python3.12.7、vLLM0.19.1、PyTorch2.10.0+cu128、Transformers5.16.1；完整旧服务依赖与配置在 `qwen3_8_27b/`。BF16，单卡，16384上下文，每请求1张图，max_pixels1605632，原批次关闭思考，temperature0.7/top_p0.8/top_k20/seed12345。

这些是原运行记录，不是已经在合作者机器验证的新环境。模型权重、系统CUDA兼容库、浏览器二进制和虚拟环境均未复制。原模型目录、端口、GPU编号/UUID只能作来源记录，应配置自己的合法模型与算力。

## 在线运行须重新配置

本次移交不自动执行旧批次脚本，不沿用旧授权、截止时间或费用豁免。先小型非图表连通性检查，再明确样本、输出目录和预算。所有密钥通过自己环境或凭证管理器提供；不要将完整task spec中的gold、机制标签或原始隐藏表输入模型。

原始提示、任务、图表、gold和旧模型输出不因移交而优化。若后续为可移植性改代码，另存版本，并在报告中与旧协议区分。
