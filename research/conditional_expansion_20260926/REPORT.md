# 条件式三字段展开：真实测试与审查

## 结论

新展开确实不再要求先证明读法适用，才允许候选成为 OBC。最清楚的例子是 b002：上轮被拒绝展开的 Firefox 柱高路径，本轮获得非空条件式记录并实际进入核验。pub013 的矛盾 KS 路径也被留下，随后核验指出内部推导不成立。

但“忠实表达”尚未全部解决：个别记录把关键观察放进 B、选择性删减相反假设，或新增平局兜底。核验也出现字段与解释矛盾、将来源偏好当作任务规定等问题。因此本轮支持保留这种阶段分工，不支持宣称所有解释都正确、已稳定纠错或已产生可用持久规则。

实际运行因第 19 次请求超时停止：14 次展开全部完成；核验 4 个单元完成、1 个结果未知、3 个未运行。旧结果未覆盖，没有为了得到好结果重跑。

## 改了什么

新建独立的 `flat_prompt.py`，130 个英文词，不在旧 prompt 上叠加补丁。只要求模型输出：

```json
{"O": ["带位置的字面观察"], "B": "条件式读法及必要假设", "C": "候选所主张的具体行动"}
```

- O 保留字面标记、空间关系，不提前做业务排名。
- B 用一个段落表达读法和假设，未核实内容仍是条件，不先决定适用性。
- C 是候选的主张，不是展开器重新裁决的正确答案；有原选项时保持原文。
- 删除模型生成的 ID、outcome、reason、嵌套条件列表、适用性等字段。程序负责关联 ID；不补造推理。
- 可以把错误候选写成待验假说，但不得为保住 C 新添观察或政策。缺材料才允许空记录，不因冲突或不确定就留空。

中文全文见 `PROMPTS_ZH.md`；实际英文及 JSON schema 都在运行快照。新提示和输出结构同时改变，不能把结果单独归因于短提示或某一个字段删除。

两种上游反问沿用：候选登记版、候选登记＋读取覆盖版。本轮只复用它们先前生成的全部候选，没有重跑反问，也不设置普通重看贡献对照。

## 两个重点

### b002：条件解释得到保留，核验仍混淆职责

新模型 O 列出 Firefox 蓝柱、Edge 绿柱、印字 23%/87% 与纵轴 0–100；B 假设物理柱高是数值来源、印字可能错误或是其他指标，并说 Firefox 柱更高；C 为将 Firefox 放入优先兼容测试队列。关键柱高比较没有放进 O，这是实际输出缺点，展示层未替模型修好。

核验收到这条链，却把公开任务的“dashboard market_share values”解释成“明确要求打印标签”，因此将 B 判 refuted、推导判 invalid。公开任务并无标签必定优先的明文规定。这里不宣告 Firefox 是最终正确行动，只说明核验没有清楚区分“若采用该读法是否能推出 C”和“此读法适不适合业务决定”。

### pub013：先表达错误候选，再检查推导

新 KS 链承认浅色 High 对应高风险，却提出深色 KS；展开器不发明反向指数来救它。核验随后指出这种桥接不成立。这符合用户要求的职责划分。但新 O 将 DE 说成深红色，核验又整体判支持，说明视觉逐项核实仍有漏项。IL 的链获支持，且原来已存在，不能算新的反问发现。

## 阶段决定

保留“反问补充候选 → 条件式展开 → 独立核验”的职责分离。下一处有证据的待解决问题是：展开的前提忠实性，以及核验能否分别处理视觉事实、读法适用性和条件推导，而非继续靠生成端拒绝候选。

本轮到此停止；不自动修改核验 prompt、不补跑超时单元、不扩展任务、不生成持久规则或继续业务执行。不能从这轮固定开发输入推断一般任务上的反问发现能力、稳定恢复或方法优越性。
