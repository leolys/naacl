# 两种反问实现：执行前独立审查

审查范围：`registration_prompts.py`、`registration_records.py`、`dependencies.py`、`run_panel.py`、`config.json`、`PROTOCOL.md`，以及实际复用的旧结构校验、展开/核验提示和本地模型传输实现。仅只读审查代码；未运行被测模型、未操作服务器、未启用 ARIS。本文不是用户人工确认，也不是效果验收。

## 审查结论

在用户明确取消普通重看对照的前提下，两个实现符合本次限定开发诊断：**未发现需要阻止这一次固定面板运行的答案泄漏、任务特定提示或强制造链规则。** 启动仍应以必要测试通过、既有服务可用和运行前资源记录为条件。本审查不要求恢复用户取消的对照。

### 提示与职责

- registration 要求登记本次实际形成的候选，不让生成器先判定是否足够新颖；同结论、不同依据和零候选均允许。没有州名、浏览器名、具体数值、答案方向或隐藏证据位置。
- “不要把刚得到的结论改作参考后再找第三个答案”针对上轮公开响应中的任务理解现象，属于可用于任意任务的登记说明，不提供本例应选谁。
- coverage 只追加文字/数值、位置/大小、颜色/映射等实际存在且任务相关的通用途径；不要求每个通道都生成候选，不要求冲突，不规定哪种编码优先。颜色与图例可能构成同一条读取路径，结果分析不能把枚举通道数直接当作独立解释数。
- 原提示已包含“将可能性放进 proposals”，原响应也是合法 JSON。因此新版本应称候选登记/任务理解调整，不能宣称只是修好 JSON 格式。

### 信息隔离、保留与预算

- register 仅接收冻结公共 context、同一完整图和旧行动标签；不给旧 O/B。源文件与输入 hash 在运行前核对；旧链只在后续统一核验时进入模型。
- 新 schema 只有 candidates 列表，无自由 notes；允许零至两个候选。所有结构合法登记在展开前写盘，没有从旧 notes 挖出 ME 等结论冒充新输出的代码。
- 容器适配仅将 candidates 传给旧 assemble 的 proposals 参数。逐个展开，保留同 C、未展开、接口失败和偏离候选的响应；偏离以标记反映，不暗中删除或改写。
- 同/异行动标记由完整公开选项标签相等性产生，不声称依据新颖。旧 O/B 未给生成器，结果中的路径新颖性只能事后检查，不能靠行动标签确定。
- 执行顺序确为先登记 8 个单元，再做展开/核验。正常上限为 8 登记 + 16 展开 + 8 核验 = 32 次；传输账本在每次实际请求前计数，40 次尝试硬上限包含重试。未知传输结果全局停止，质量/结构失败不自动重试。
- 客户端硬限制为 `127.0.0.1:8058`、不信任环境代理、禁止重定向；无付费后备、浏览器执行器调用或 GPU 启停。旧模块虽然包含 actor 类，但本轮没有实例化或调用它们。
- 旧依赖 hash 检查、源快照、请求/响应/图像身份与一次运行锁均存在；没有写入旧结果的路径。

## 必须保留的解释边界

1. 两版只在 coverage 追加的通用读取说明上不同，使用相同 schema、图片和下游；但本轮每单元一次、仅四个已用开发输入，不能作稳定因果或泛化估计。与历史版本还有登记 schema/notes 改动等差异。
2. 非空登记不等于新增解释路径；同义重写、重复旧依据不算补全。不同 C 也可能来自读错、虚构或改变业务指标；应逐条展示原图 O、映射 B 与条件结论 C，而不是只报数量。
3. 原链和新候选均允许有错，但“无需先核验”不授权虚构观察、任意倒置指标或假定答案。保留这些输出用于审查，不把它们直接计作有价值覆盖。
4. 核验器沿用旧版本，已知有将不可见证据视作反证、将 B 不适用混同条件推理无效的问题。此次保持不变有利于控制改动，但其枚举通过不是效果真值。
5. 无 actor、真实提交或新自然前缀。本轮不能得出业务纠正、持续恢复、自然检测率，也不用于论证反问相对普通重看更优。
6. 正常图已有 Clean 说明、pub013 原有两个结论等历史限制继续保留。没有新增本身未必失败；输入误读导致的空输出与确无额外依据必须区分。

完成冻结面板后，以完整实际请求和响应再审查；不因结果不佳扩样本、加提示版本或质量重跑。
