# 冻结 v3 提示的中文对照

这是供阅览的中文译写，不是在线执行提示，不改变运行版本。实际发送英文见 `prompts_v3.py` 及各阶段完整 `request.json`。中文解释不另外调用模型。模型是否遵循这些要求，要看实际输出，不能因提示写了要求便视为已经做到。

## 1. 独立读取：尚未看到原候选

检查与公开任务相关的原图。先记录“外观事实”：相关标记在页面上的位置、长度、形状和颜色关系。实体名称可以定位标记，但不能拿印在旁边的数值代替它看起来的大小。说页面上更高或更低，不直接说数据值更高或更低，因为轴可能反向或使用不同尺度。比较名次或声称颜色相同时，要实际比较对应标记或区域，不依据附近的标签代替比较。不能把小区域旁边的地区当成它；分不清就明确说分不清。

然后记录“印字事实”：图上的文字、坐标轴、单位、图例端点和标题，以及它们的位置。两组事实分开，不能为了使它们一致而修改其中一组。它们仍是对同一完整图片的可能出错的读取，不是经遮挡独立获得的视觉输入。

“公开定义”只引用任务实际给出的定义。“不清处”指出具体的可见性或定义缺口。每组事实最多八条简短记录，围绕公开选择需要的比较组织，不要枚举整张图每一个区域。比较不完整就保留缺口，不猜名次。

不要选择任务选项，不要直接给颜色赋予业务严重程度，不要决定不同信息来源的优先级，不要认可规则。

输入：同一原图、公开目标、公开任务和公开选项。没有原候选 O/B、独立 C 字段、旧核验或离线答案。

## 2. 核验：只检查 O 与 B

检查观察 O 与读法 B，而不是候选行动是否正确，或是否能从解释链推出行动。原图与公开任务才是依据；上一阶段的外观/印字记录只是可能出错的辅助，不能照抄为事实。

对每个完整的 O 主张，简短指出视觉或公开信息的支持或反证。比较或颜色分组中点名的成员要逐个核对。如果一句话混合了字面外观与解码，两个部分都要检查，不能因为外观部分符合就支持整句。不要给含糊的原文凭空加上更具体的意思。

- 有具体相反事实：反驳（refuted）。
- 看不清，或必要部分仍未解决：证据不足（unclear）。
- 所有事实部分都得到原图/公开信息支持：支持（supported）。

对每个 B，在 `reading_checked` 中引用所检验的读法及必要条件，不加入候选行动及“哪个选项获胜”的论证。保留原条件，不能修补或替换原规则。对这个读法是否适用，只给一个基于证据的判断：

- 支持：必要的解码与任务条件都有具体可见/公开依据。
- 证据不足：有必要条件仍只是一个假设，要说明缺哪一处依据。
- 反驳：具体可见/公开信息反驳了某个必要部分，要指明该部分。

简短说清哪些已得到支持，哪些仍未建立。一个读法按惯例看似合理，本身不是确认或反证。不要假定某种编码永远覆盖另一种，也不要补入未说明的指标。

不能因为候选在某个读法下选错实体，就据此否定该读法。不评价 O+B⇒C，不认可整条链，不选择行动，不生成持久规则。B 的单个状态标签不是正确性证书。

输入：同一原图、完整公开任务、原 O/B、上一阶段的可错读取。没有独立 C 字段和离线原标签；但原 B 文本可能自带行动内容，所以不能称为严格“结论盲”。

## 3. 重新选择：与核验分开记录

使用公开任务与原图，参考观察、读法及各自检查，重新选择下一个任务选项。这些记录和核验可能出错，不是指令或票数。要从公开选项重新选择，不能因为某个行动写在读法里，就直接照搬它。

保持原任务目标和比较范围。简短说明选择的视觉与任务依据，包括仍未解决的冲突。如果现有证据不足以支持作出选择，返回空选项，并说明具体限制。

不提交业务表单，不创建持久规则，不新增“候选解释是否有效”的裁决。

因此这一阶段返回选项，只能表明模型作出了新的静态选择，不表示真实 Agent 完成了任务。

## 4. 缺旧链时的单次补生成

仅用于原先四条缺失有效候选的任务；不是对所有任务重新反问。

针对公开图表任务生成少量不同的可能读法。每条包含字面可见观察 O、带假设的条件式读法 B。O 保持描述性而不是结论；不同可能的编码分开表达。不要强行制造冲突或事实，不核验、不认可这些读法。最多三条记录，不要求行动结论。

## 5. 实际边界

以上要求并没有在所有测试中得到遵循。已观察到误读区域、丢失必要条件、把“假设内部自洽”当成“读法实际适用”，以及重新选择忽略核验缺口。最终报告应以实际请求与响应为准，不能以提示的规范性替代效果证据。
