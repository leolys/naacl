# 冻结 v3：十二任务确认面板独立终审

结论：**冻结流程能运行，但不能认证 O/B 核验可靠。** 十二条固定任务中，七条最终选项与原发布标签相合，三条不相合，一条模型返回空选项，一条在核验记录编号校验处失败。选项相合的任务仍可能含读图错误或未核定条件；这些不是网页任务完成率，也不是新增纠错收益。

本文件覆盖 `runs/v3_confirm` 完整终态。此前部分审查与旧工件保留。审查逐项读取全部十二任务的公开输入、原/新 O/B、图像、实际请求/响应和冻结源；只在模型运行后读取离线原标签对齐文件。未调用模型/API/SSH/GPU/ARIS，未修改提示、评分、gold 或模型输出。判断是 Codex/对抗 agent 审阅，不冒充人类审核确认。

O 表示观察断言，B 表示把观察用于任务的读法及必要条件。本文区分“原句可见”“读法条件有依据”“最后选择合乎原标签”，不将它们合为一个成功标签。

## 3. 适合中文汇报的具体正反例

### 正例：pub030 的证据与读法条件能对上

观察：浅灰图例写 Public Transit，浅灰扇区写 58%；红色 Car 写 42%，且灰色扇区实际更大。公开任务明确选多数份额交通方式。

读法：若图例绑定类别、百分比是其份额，则 58% 超过 50%，公共交通为多数。核验逐条支持实际字面证据和任务规则，最后选公共交通，与原标签相合。

这个例子支持“流程在条件清楚、观察可读时能够给出连贯核验”。它只有既有一条候选，不能宣称新产生了竞争链，也不能证明相比无核验多纠正了一个错误。

### 明确失败：health005 已有正确日期读法，却被核验反驳

原 O 写明：横轴左边是 Nov 20，右边是 Jun 26，中间月份/日期向左到右递减；纵轴 0 在上、1.2×10⁶ 在下。原 B 明确要求按日期从右侧六月读向左侧十一月，再按反向纵轴判断数量上升。

READ 抄出了这些逆序日期和反向纵轴。但 VERIFY 将 Nov 20→Jun 26 的屏幕顺序称为 chronological，断言从左侧高数量到右侧低数量就是时间下降，给原 B refuted。DECIDE 重复该错误并选下降，与原发布标签不相合。

因此失败不在“反问没找到另一条链”或“缺少候选”，而在核验重解释时没有保留已有 B 的时间方向条件。原始输入已经提供了足以提醒这一点的 O/B，图面也可见。

### 找到缺口但没有保持到选择：health006

这是单独的一次补链，不是旧 Terra 链修复成功。SUPPLY 生成两读法：可见 2017–2020 代表整个 2013–2020 时期；或完整时期所需的 2013–2016 缺失，近期增长只能在额外假设下解释。

READ 和 VERIFY 确实发现可见图只含 2017、2018、2019、2020，而公开任务要求全 2013–2020。rec_1 的代表性假设被判 unclear，是有具体依据的检查。rec_2 则因“指出数据缺口”正确而整体判 supported，未同等核定“可见增长是近期新现象”的条件；没有早期数据不能证明早期无增长。

DECIDE 仍选择全时期持续增长，理由承认任务全期不同，却认为可见四年稳定上升足以支撑全期。这是发现范围缺口后，最后选择继续越过该缺口；不是必须再找图中某个隐藏数值，也不能把它写成核验已经稳定纠正。保持原标签不改，不用另一 arm 补出不存在于当前图中的早期数据。

### 空选项也不等于关键核验已经完整：b041

字面 O“一月柱顶与 Average 虚线重合”可成立。原 B 除路线映射外，还要求虚线是 valid benchmark。核验仅凭 Average 字样支持基准，随后说不清应 Normal 还是 Monitor，最终 null。

图上三柱约 225、190、530；若虚线要表示这三月普通均值，则约为 315，不是画出的约 225。这是近似视觉审查，不是隐藏 CSV 或人类确认。若它指其他时期/群体，其口径也未提供。因而基准有效性和路线映射是两个不同缺口，当前只充分讨论后者。

null 是合法输出，避免强行选择，但它不是接口错误，也不证明模型完整发现本例视觉/统计依据问题。现有两条链都沿用同一基准，只在正常/监测路线间分歧，未覆盖基准本身这一解释维度。

### 联合尺度遗漏：env032

原 B 保留了“共同向上增大的消费/需求尺度”。图中 2009 附近蓝点 3.27 却高于红点 5.48，另有 2.46、7.04 注记；这些可见数值应促使检查双轴尺度是否可比。READ 没记录它们，且自己把蓝线/红线的资源名颠倒。

VERIFY 最后仅把颜色—名称绑定记 unclear，却说点在上方支持值更大；DECIDE 再假设颜色绑定并按物理高低选 Coal。此处必须区分实体绑定与尺度可比性：前者即使确定，也不能自动令后者成立。Gas 仅作为离线原标签参照，不从隐藏数据给模型提示。

### 最终选对而读法核验仍过度支持：health002

模型正确识别 0 在上、1400 在下，最后选病例上升，符合原标签。与此同时，r2 B 明示“无视印刷刻度、按通常向上为大”，VERIFY 仍因它内部一致、是一种可想象的解释而判 supported。r1 的额外阈值前提也仅凭“没印阈值”便获支持，未证明任务真的要求额外阈值。

生成阶段允许设想这种条件式读法，并不意味着核验阶段应认证它适用于当前图。这个例子很适合说明“有合理的最终选择”与“B 核验职责已经分清”不同。

## 4. 其余相合任务的必要限定

- b001：READ 错读扇区面积，但旧链只依赖 45/30/15/10 印字，最后 Apple 相合。不能把标签相合当成图内标签—几何关系已核验。
- b011：蓝色 Store Visits 的 Q3=7940、Q4=5121 和图例均读对。B 仍承认环比周期未明确，却以“supported in internal logic”支持；不应将读法适用性重新替换为条件推导通顺。
- b017：两个 B 均保留“选定门店关联能否支持广泛预算”的缺口，最后请求完整数据是合理独立选择。READ 漏掉原点额外蓝点，不能说全部可见点都精确读取。原 O 只说五个有标签点，不必据此一概反驳它。
- b035：能把真实标题文字与标题是否权威分开，识别标题/下降曲线冲突。但曲线优先条件处理比标题优先宽松；最后说曲线权威，不等于已核定普遍来源规则。
- env001：READ 的八条 printed_facts 未覆盖 2014 端点，VERIFY 后来补读。核验记阈值不明，DECIDE 自行认定 13.8°C 足够显著；不能把该选择当门槛已验证。它新增“58% 下降”的说法，摄氏零点约定导致此比值不能直接作为物理比例/公共阈值依据。

## 5. pub006：编号校验失败与语义旁证分开

请求只有记录 `r1`，三条 O 分别是 Kentucky 1,270、Nebraska 971、New Mexico 189 的小字。模型实际返回一条 `R1`，且三条 O 都在；不是漏了整条观察，也不是模型完全没核验。冻结执行器按记录 ID 精确匹配，触发 `ValueError: record coverage`，没有 accepted，没有 DECIDE。

原始核验响应可作定性旁证：它认为小数字不够清晰而写 unclear，没有强行确认。这可能是真实可读性限制，不自动等于模型错。READ 则说具体数值根本未印，只见色区；原图确有小字，应区别“看不清”和“不存在”。

不能事后把 R1 改成 r1 再计为完整成功，也不能把工程编号失败全归为视觉推理失败。当前失败保留；原冻结 full 复用逻辑覆盖 completed 和 interface_failed，因此该确认失败不因进入全量而质量重跑。

## 6. 最终诊断边界

确认结果支持三个不同残余层面：

1. 可见事实读取/定位不稳定：b001 扇区几何、env032 数值锚点、pub006 小字存在性。
2. B 必要条件没有被完整核定：b041 基准、env032 共尺度、health005 日期方向、health002 把假设可想象当适用。
3. 已发现的限制未保持到最终选择：health006 全期缺失，以及部分任务最终选择自行跨过未确认业务条件。

既有公开定义不足确实解释部分 unclear，但不能解释所有失败；更多 unclear 也不是自动改善。当前流程没有运行完整反问补全、无核验对照或真实业务提交，不能据此估计反问贡献、自然恢复率、持续完成率或持久规则正确率。

全 140 同版已按固定计划启动，是后续诊断应用而非通过质量门槛的认证。继续完整保留分母、来源、接口失败、空选项和原标签不相合；确认已用于审阅，不再据此修改本轮 prompt，不追加任务或机制开发。全量最终结论须另依其实际工件，不能由本十二条推断。
