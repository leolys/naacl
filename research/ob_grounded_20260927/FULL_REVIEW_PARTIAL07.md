## 2. env035：倒轴方向与指标归属分别看

证据：`data/full_env035/{input.json,chart.jpeg}` 及 `full_env035/{read,verify,decide}`。

### 图和公开任务各自提供什么

图标题为 `Year vs. Price in U.S. dollars per barrel`，纵轴却标 `Count`。纵轴 0 在上、5 至 35 依次向下，1980 的蓝点是所有点中页面位置最低者，按该刻度对应约 38；1976 在页面较高处，对应约 12。

公开目标明确要求最高 per-barrel cost；`chart_reference` 更直接描述此 dashboard 为年份与美元/桶价格。故“价格”不只来自图标题，也来自原公开任务。这一点不得在审查中删去。

### 模型实际完成的工作

READ 同时列出了反向刻度、1980 最低页面位置、约 38 的读数，以及 Price / Count 的冲突。VERIFY 支持七项原 O，图面确有相应依据；没有把页面最上方的 1976 当数值最大。

原 r1 B 是条件式保留意见：若 Count 是权威指标，或无法建立数值为美元/桶，则不能直接当价格。其 conditions 还要求明确的 y-axis 指标标注。模型给 supported，主要理由是 Count 与标题不一致、冲突未解。

**这里 supported 不能解读为已经证明 Count 是实际业务指标，或证明纵轴标签一定比任务说明权威。** 冲突存在是可见事实；“必须由 y 轴单位解码”的条件并不会仅因冲突出现就自动成立。

原 r2 B 保留另一条解释：若任务/标题决定价格含义、把 Count 视为误标，则按向下增大的刻度找最大价格。VERIFY 明确保留这个必要假设，给 unclear；没有把 Count 原文删除，也没有确认它必然是误标。

DECIDE 实际收到上述两项核验。它援引**图标题和 task description 都指定美元/桶**，再使用正确的倒轴方向，选择 `Route 1980 escalation review`。最终理由没有再讨论 Count。

### 可以与不能声称的结果

- 可以：模型在此例读对倒轴与最大值年份，给出了与原目标相同的静态选项；决策理由有公开任务的指标描述作为依据。
- 可以：核验记录了指标冲突，但最终理由没有显式交代 Count 应如何处理；倒轴解码与语义归属是两层问题。
- 不可以：把这个单例说成已实现持续 Agent 恢复，或所有 B 的必要条件均获确认。
- 也不宜反向夸大为“1980 毫无公开依据 / 只因盲信标题”：公开任务本身明确指称价格。最终选择可以不同于 fallible checks，是否充分解决冲突须看所给理由，不能仅以先前存在 unclear 判它必错。

原 gold 保持 1980；没有网页提交、行为回滚或持久规则。

## 3. env033：关系误反驳与漏掉校准线索

证据：`data/full_env033/{input.json,chart.jpeg}` 及 `full_env033` 全部三阶段请求/响应。

### 原图不是没有任何数字

公开任务要求比较 2010 的 Hydroelectricity 与 Nuclear energy。左蓝轴和蓝圆线对应 Hydroelectricity，右红轴和红方虚线对应 Nuclear energy，两侧均写百分数，但没有数字刻度。2010 红点在页面上高于蓝点，且两个 2010 点没有直接百分数标注。

以上都是真实可见情况。但图的**其他年份**有四个清楚可见的数值标注：2015 蓝 35%、红 23%，2035 蓝 47%、红 28%。所以“2010 没有直接印字”与“图上没有任何标定数值”是两句话，不能替换。

### 一个直接的 O 关系误反驳

原 r2.O2 是：2010 蓝圆点在页面上**低于**红方点。这与原图一致。

VERIFY 给 refuted，evidence 却先说：2010 红方点在页面上**高于**蓝圆点；随后又说原“蓝点低”是错误的。

两者表达的是同一个高低关系。因此这是错误反驳和理由内部的直接矛盾，不是原 O 没有视觉依据。它没有必要依赖 gold、隐藏数值或线性尺度才能被发现，也不是 O+B⇒C 的推理核验问题，而是对 O 自身关系的核对错误。

READ 自己也读到红点页面更高；其中另一条 appearance fact 却说红点对应“更高的 y-axis value”，已经从跨双轴的页面高低跳到数值高低，尚无尺度可比依据。这与后续 B 对双轴比较的提醒也不一致。

### 双轴提醒合理，但“绝不可能”遗漏了图面资料

VERIFY 的 r1 B supported 主要确认任务要路由较大者，且没有 unresolved→archive 的回退规则；没有把缺证据自动等同于应该选 archive。

r2 B supported 强调：不同轴不能仅凭屏幕高度比较，须解码可比数值。这条提醒本身正确。问题是 evidence 进一步说公共图无法解码、确定比较不可能；DECIDE 也按这个理由 null。

实际 READ 的 printed_facts 没列出 35%、23%、47%、28%；VERIFY 和 DECIDE 的对应理由也没有讨论这些已可见的其他年份标注。因而“仅看这张图绝不可能解码”没有充分排查现有依据。

### 一条必须带假设的离线推算，不是追加金标准

若**明确假设每条序列各自使用线性纵轴**，两处已标注点可分别提供该系列的数值—页面位置对应；不要求蓝红共用同一个轴尺度。

- 蓝 2010 点在 35% 标注点下方，距离约为蓝 35%→47% 页面跨度的四分之一，可粗估 `35 − (47−35)×1/4 ≈ 32%`。
- 红 2010 点在 23% 标注点上方，距离约为红 23%→28% 页面跨度的六成，可粗估 `23 + (28−23)×0.6 ≈ 26%`。

这些是按当前图面位置和**显式线性假设**作的近似推算，不是隐藏原始值、精确像素测量或新增人工审核。若不接受线性尺度假设，数值仍可能存在不确定性；本审查不强行宣称已无条件证明唯一业务答案。

它只说明：图里存在模型没讨论的进一步解码线索；“缺少数字轴刻度”不自动等于完全没有任何校准办法。更准确的限制应是“尚未检查其他标注能否在有根据的尺度假设下恢复比较”，而不是已经证明绝对不可解。

此推算未发给模型，没有据此补跑、换原输出或调整提示。原 gold 仍为 Hydroelectricity；null 没有给出原目标选项，但其接口真实完成，与未运行/异常不同。

## 4. 汇报边界

env035 提供具体的读轴成功与静态选项命中，同时保留指标标签冲突的处理限制。env033 则同时包含合理的双轴提醒、一个错误 O 反驳和未被利用的可见数值线索。

不能只用正确选项给整套核验背书，也不能只用 null 给“谨慎核验”背书。这里的结论来自图、原文及实际请求，而不是依据 gold 选择性解释；本批不新增历史 evidence_conflict 标记，不调整冻结运行，不扩展机制开发。
