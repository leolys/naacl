# v3 完整开发面板：独立对抗终审

结论：**可以冻结 v3，作为全 140 条的“有已知限制的静态诊断候选”；不能认证为可靠核验方法。** 8 个单元都执行完毕，部分柱高、色阶和读法职责错误改善，但仍有可见事实错读、必要条件被跳过、来源优先被臆定及引用协议不遵循。按照预定边界结束开发，不开第四版、不据确认结果修改提示。

本文件覆盖 `runs/v3_dev` 完整终态，部分快照审查保留不改。审查只读本地原图、原 O/B、实际请求/响应、冻结源码；未调用模型、API、SSH、GPU 或 ARIS，未改变旧记录，未查看确认组模型结果。以下语义审阅是 Codex/对抗 agent 审阅，不冒充用户的人工确认，不修改原 gold。

## 1. 执行与信息隔离

独立核对全部 24 个实际请求：8 READ + 8 VERIFY + 8 DECIDE，全部 HTTP 200、finish_reason=stop，0 次重试。24 个 accepted 都与相应原响应 JSON 相等，没有解析后语义修补。

四个图输入各自的两份 READ 请求文件完全相同。只有 pub001 正常的两个 READ accepted 也相同，其余三对有差异。因此固定 seed 没有保证本次服务完全确定；不能把 READ 差异解释为候选来源影响，因为 READ 根本未接收候选。重复请求来自预先固定分支，不是按结果重跑；8 个单元仍只是 3 基础任务、4 图输入 × 2 候选来源。

## 3. 能保留的局部改善

v3 两份 b002 的主要 appearance 项都读出 Firefox 高于 Edge，并单独列出 Firefox 23%、Edge 87%。这比 v2 registration 将几何读反有改善。coverage/b002 也正确反驳了原 O“Firefox 第二高”。但本轮没有证明整个独立读取准确，更没有证明文字影响被隔离。

pub001 正常 registration 反驳 MN/AL/AK 与 ME 同最深色，coverage 至少反驳 AK，且 coverage 正确区分整图标题与图例文字位置。相对 v2 的全部支持，有具体可指认改进；剩余相同色阶误读仍不能删去。

两个 pub013 的逆向指数 B 都写明未确认必要条件并判 unclear，避免只因“不常见”就立即反驳。registration/pub013 r3 虽未从 reading_checked 删除旧 KS 行动，但 evidence 明说那是候选行动而不是地图事实，没有再次用“KS 不符合这条读法”反驳 B。这是职责层的真实局部改善；不意味着该读法所有语义均已验证。

v2 的 coverage/pub013 因枚举过长截断，v3 能完成短读取。该接口改善伴随输出格式/条数约束变化，不能单独归因于“先观察外观”。

## 4. 仍阻止可靠性结论的问题

### 必要任务条件仍可被已支持的解码部分取代

registration/pub001 误导 r3、r4 的 B 分别假设优先最低值、优先最高值。模型承认优先条件不是公开定义，却仅凭图例支持各自解码就都判 supported。问题不是“两条候选不能同时存在”，而是本版 supported 定义要求必要任务条件也有依据，当前理由绕过了这个要求。

同一图的 coverage 将这两条件都判 unclear；正常图 registration 也都判 unclear，而 coverage 又以“standard/reasonable”支持最高、反驳最低。公开任务没有因为候选来源改变而新增规则。单一 B 字段减少了结构复杂度，但没有稳定解决证据门槛问题。

### b002：不是看到冲突就守住了读法评价

registration/b002 r3 承认 Firefox 柱更高，却明示“dashboard 中印字默认是主要数据来源，除非明确另说”并判几何读法 refuted；DECIDE 延用该规定。coverage 进一步把公开的 dashboard values 擅自括号化成 printed labels。公开任务没有宣布这个永久优先级。

更直接的退化是 coverage/b002 r2：原 B 要求柱高与市场份额正比、印字确认幅度。v3 自己承认柱高与标签矛盾，却因为标签选 Edge 而支持整 B；v2 曾将这个视觉解码条件反驳。即使 Edge 最终符合原标签，也不能修复已被反证的比例假设。这里只判断原条件是否有依据，不需要重新引入 O+B=>C 核验。

独立读取本身也有内部错误：registration 写 Safari≈20 却称第二矮，Others≈14 却称第三矮；coverage 写 Safari 比 Chrome 矮同时给出 20 与约 12，又在 uncertain 内称 Edge 明显最高，和同一输出的 Firefox 最高冲突。不能把主要比较读对简化成“已可靠分离几何与数值”。

### 两个 pub013 的 DE 观察未修好

源图 DE 是靠近深红 MD 的小区域，不是 KS 那样的深栗色。registration READ 写 DE 深红，核验却同时支持 r1/O5 的 medium red 与 r3/O4 的 dark red/maroon；coverage READ 直接写 DE 深栗色，r1/O5 原文是 medium red，evidence 却改述为 dark maroon，最终 supported。

coverage 此项属于原断言、理由内容与支持判定未对齐，且没有后文撤回。它不同于 registration/b002 r1/O3 的中途 Refuted：后者已经自行重查、明确确认 5% 字面标签，末句和最终 supported 一致，不应再夸大为未解决字段矛盾。

pub013 正向 High=高风险有标题和任务语义依据，比任意反向定义更自然；但理由中“not contradicted/standard/plausible”仍不能自动升级成所有必要条件均已确认。不能机械要求正反全部 unclear，也不能用最终 IL 替这些核验依据背书。

### 看不到界面状态，不等于相反，更不能幻觉可见

pub001 误导 r1/O5 说 dropdown 当前为 TX。registration 因公开文本没确认而判 refuted；coverage 更直接声称 dropdown 在图中可见并判 supported。实际两者收到的是同一静态地图，不含表单当前状态。一个误把缺证据当反证，另一个编造可见依据，都应保留而非选择较有利解释。

### 引用与职责仍未统一

28 个 reading_checked 中，仅 5 个能按原 B/条件的顺序文本找到直接摘录：registration/pub013 的四个及 coverage/b002 r3。其他 23 个是概述，有的将当场核验判断塞进 reading_checked；文字不等于原文引用。

直接摘录也不保证职责正确：registration/pub013 r2 几乎复制整段旧候选推理、各选项及行动；原文含“这些生成任务”的猜测，这些不是新观察或公共规则。概述也有删条件的风险，如 registration/b002 将“标签可能错误或代表另一指标”缩为“可能错误”。应公开这些偏离，不能在事后展示里把它们改成更忠实的输入。

## 5. 冻结决定与允许的全量解释

可以冻结 v3，理由是三版开发边界已到、固定面板已完整、输入/输出和成本可追溯，且后续 140 本就预定为诊断应用；**不是因为八次都生成目标选项，或核验问题已被解决。** 不推荐第四版，不拿确认结果改提示，不用全量成功样本反选“最佳版本”。

全量应保留全部 140 分母、旧 Terra 候选与开发 Qwen 候选来源差异、4 个缺链任务的一次补生成、接口失败/核验未运行/已执行核验问题。确认子集可按原协议复用已完成同输入结果，不能重复计费后选择较好响应。分家族报告变式关系，不把 140 当 140 个独立语义任务。

可成立的表述是：“完成一个冻结的全图观察—O/B 核验—重新选择诊断流程；开发面板可解释地改善若干局部错误，同时暴露通用证据判定和小区域识别的残余限制。”不能据此宣称可靠核验、稳定网页恢复、可信持久规则或全 140 泛化已证实。

## 6. 离线原标签对齐脚本审查

已只读检查 `export_original_labels_offline.py`：未连接模型或浏览器，不提交，runner 未导入它；它从原 action_options 导出唯一 correct 角色，只在标签及顺序与冻结公共选项完全相同时对齐，重名/无唯一 correct 则不评分，输出使用独占创建避免覆盖。它不是原 scorer 执行，也不是新人工审核，脚本已有相应标识。

首次审查版本只检查 FREEZE.json 存在，未核验其绑定的 manifest/source 哈希，也未逐 input.json 比对 manifest 的输入哈希。主执行者随后已补充检查；本审查再次只读确认：现在逐项比较 freeze.runtime_hashes，逐任务比较 input.json 和图像哈希，不匹配即报错停止。被测模型协议未因此改动。本审查没有运行标签导出或读取新 gold 来优化提示。

标签对齐即便全部通过，也仅支持“选项与原发布标签相合”的统计，不能充当 O/B 语义准确率、提交成功率或既有人工审核被重新确认。
