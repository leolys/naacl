## 通用性与职责边界

- READ 先输出 appearance_facts，再输出 printed_facts。前者要求页面上的高低、形状、颜色关系，明确页面高低不等于数据高低，避免对反向轴/异尺度默认套用普通柱高意义；后者记录印字、刻度和图例。没有实体名、样本 ID、答案或某编码固定优先。
- 每类最多 8 条，限制全国/全图枚举；没有裁图或隐藏对象。提示要求不完整比较保留缺口，不能把未写到的对象当不存在。appearance 至少 1 条、printed 可空，结构校验并不强制编造具体名次。
- B 简化为 reading_checked/evidence/status，仍保留原完整 B 输入。supported 要有必要解码和任务条件的具体依据；必要条件未确认则 unclear；有具体相反依据才 refuted。不是把两个子项中最有利的一个当整 B 支持。
- reading_checked 要引用原读法与条件、排除候选行动，不允许修补 B；VERIFY 明确不评价 O+B=>C，不判整链、不提交、不生成持久规则。没有重新引入 inference 字段。
- 新读取结构在 runner 中作为不透明笔记对象传递；核验记录同样直接传入 DECIDE，没有依赖被删的两个 B 子轴的确定性执行逻辑。DECIDE 仍重新选择公共选项或 null，不强行落到 supported 数量最多的结论。

## 仍需从实际结果检查的风险

1. 全图同一次输入同时可见；输出顺序不是感知隔离，也不能证明模型先看形状后看文字。先写 appearance 仍可能受标签影响。v2 相同请求不同读取结果已说明一次改善不足以证明稳定性。
2. 8 条上限是通用容量约束，但可能遗漏任务需要的比较，尤其多系列、双轴和多候选图；只能记为未充分观察，不能“没写出来”即算没有证据。标题一条也能结构通过。
3. reading_checked 的条件完整性、行动排除及引用忠实性没有代码语义证明。模型可摘掉不利假设、只支持容易部分、用 customary/standard 替代依据；必须对原 B 审查。
4. 单一 B status 可以减少两轴互相代替，也可能掩盖“解码支持而任务定义缺失”。evidence 必须明确写哪个部分已支持、哪个必要条件未确认；否则不是更可靠的简化。
5. O 中存在混合断言，不能只因颜色正确而支持错误映射；图上看不到表单不能证明旧表单状态为假。新 prompt 提到这两类边界，但是否执行仍待结果。
6. 本版同时改了提示、字段结构、读取条数上限与 B 判定粒度。只能报告整体版本的开发差异，不能把改进归因于“外观优先”单一原因。未改变 DECIDE 也意味着其来源优先臆测仍可能存在。
