# 固定结论搜索面板：离线设计对抗审查

2026-09-26。仅本地设计/既有工件阅读；没有调用模型、SSH 或 ARIS。该文件是普通 sub-agent 的方法审查，不是人工金标准确认。

## 审查意见

经讨论修订后的方案可作为**已知开发例上的固定探索面板**：复用 pub001 两个真实 checkpoint 及各自原初始链，预先固定三个方案、全部跑两种图条件；所有方法分支均进入相同核验与普通 actor，不按 Codex 视觉判断或隐藏正确答案挑选运行路径。每个方案的成功、无新增、再次误读和最终失败都保留。

这不是新的自然前缀抽样，也不是独立泛化验证。方案冻结后不应再依据本例结果改提示追加未登记版本；100 次请求尝试、300 次浏览器操作和串行要求是本轮总上限，不是每方案额度。下文后备 V4 是收到进一步设计提议后的单独增补审查，不代表已经执行。

## 1. 三方案的解释及有效比较范围

| 方案 | 本轮实际改变 | 可以检验什么 | 不应声称什么 |
|---|---|---|---|
| V1：仅行动结论 | 反问不接收旧 O/B/自然语言理由，只接收去重的原非空公开 option_label；保留同一 state/history/图像 | 删除旧论证记录后能否重新提出其他行动结论 | 不能说只改变了一个词；去重和压缩也改变了先前候选的呈现 |
| V2：逐公开选项假设搜索 | 与 V1 相同输入权限，显式逐项考虑真实公开选项，允许没有可形成的候选 | 更充分的备选行动搜索是否有增量 | 选项被列出不等于有图面支持，更不等于应当选择它 |
| V3：不提供旧候选记录 | 问题生成不接收旧候选，但保留正常公开状态、历史、选项和图像；共同补充器仍接收旧链 | 候选记录隔离的独立搜索是否发现遗漏 | 不能称完全去锚定；旧选择仍在 state/history/控件截图中可见 |

三个版本改变的信息与搜索支架不同，应作为不同方案分别报告，不把全体差异都归因为“反问方向”一个变量。

共同补充器仍接收完整旧链是有意保持的下游条件：若问题阶段已产生新搜索目标而补充器回到旧读法，这恰是可定位的阶段结果，不能暗中删除下游旧链后仍声称同一方案。

## 2. V1 的 C-only 必须真正去掉隐含依据

旧 pub001 的 C.claim 本身已经带有视觉依据和因果措辞。仅删去 O/B 字段而把自然语言 C 原样传入，会继续向反问提供旧解读。因此本轮应采用确定性投影：

- 只取非空、精确匹配公开选项的 C.option_label，去重；不传 C.claim、旧 notes、旧核验、链条 ID 或重复次数。
- 离线保留原始 C 与投影来源，不改写旧结果。
- 这应命名为“仅行动结论”，不宣称支持一切否定命题/比较命题的通用 C 提取。
- 对没有 option_label 的链，本轮投影不支持；明确记录，而不是让 Codex根据图或答案总结成某个选项。

当前公开选项、当前选择和真实历史是正常任务信息，三个方案应一致保留。它们依然可能造成锚定，本轮不把这种残余自动归因旧 O/B。

## 3. 逐选项搜索不是强迫替代答案

V2 可以强制“考虑每个公开选项”，但不能强制“给每个选项找到理由”。应固定公开选项顺序，考虑原行动在内的全部合法选项，允许 no candidate / already covered。

每个选项先是一个搜索假设，不是事实。生成应始终保持实际公开任务不变：不能为了某选项成立，发明“本题其实应选最小者”一类新目标、外部政策、被遮挡数值或不同业务需求。解码假设可以尚未核验，但必须由图面或公共信息引出，不能只是“假设这个选项就是所需答案”的循环前提。

候选可以错误，后续核验负责指出其问题；这不意味着错误观察、任意规则和纯条件句都应算作解释覆盖进展。统计时至少区分新增行动标签、完整 OBC、独立核验状态和离线可见证据审阅，不能只看记录数。

在线提示不应加入本例的州名、答案、具体颜色、色条方向、错误位置或“原图有反转”之类线索。本轮已有错误是开发动机，不是模型的新公开证据。

## 4. V3 及去重的边界

建议 V3 只负责在没有旧候选记录时提出图面搜索问题，由同一个补充器决定形成新链、已有覆盖或未形成。现有问题 schema 只有自然语言 question，程序不能可靠判断其语义与旧结论重复；不应让 Codex在中间凭理解选择性过滤问题。

最终产生的 C.option_label 可用于确定性的**行动标签新颖性**计数，但同一标签可能有不同解释依据，不同标签也不自动构成逻辑矛盾。两者分别报告，不混为“竞争链数”。

## 5. 不允许真值门控决定是否给 actor 机会

最初“有不同且可见支持的新链才接核验/actor”的表述会产生选择风险：谁判可见支持？若由 Codex掌握图和答案后决定，就会让开发者成为隐藏的被测 Agent；若仅放过模型自称支持的候选，也会排除核验自身的错误。

已同意的修订是：**每个固定方案、每个 arm 均运行同一核验和普通 actor，不管是否新增。** 核验不选赢家、不改旧 C，actor 可自行保持或改选，只有它真实提出提交时才提交。程序不以隐藏 gold、人工读图结果或规则 active 状态锁定某个选项。

正常的结构失败、服务停止或未能重建状态应单列；不能人工修复模型 JSON 再把它计成原真实输出。

## 6. 预算、旧状态重建与结果选择偏差

- 两个历史 checkpoint 均使用真实动作回放；临时 URL 端口差异只能做精确的非语义规范化，截图、公开文本、控件选择和历史回执其余内容应相同。
- 先冻结全部三方案提示、配置、既有初始集合及任务 manifest，再运行；不是看到某个颜色映射错误后临时新增针对性提示。
- 每次失败、服务重试、浏览器重放、流程控制和调用都计入同一本轮账本。继承历史状态不意味着继承历史已用预算；旧结果只作来源，新成本如实单列。
- 不把三个方案里最好的一个结果单独展示为一次成功复现。完整呈现三方案及先前失败尝试，标明开发搜索过程。
- 闭环若成功，先称“在固定已知错误状态上发现了另一行动候选/完成纠正”；不能称自然检测率、独立基准改进或整体方法可靠性。

## 7. 推荐预先固定的分层输出

1. 输入投影：模型究竟看到旧链、仅行动标签，还是没有旧候选记录。
2. 问题：数量、搜索目标、是否真的提出不同结论；零问是可观测结果，不是补充器失败。
3. 补充：新增完整链、已有覆盖、未形成；同结论新依据与新行动标签分开。
4. 核验：观察、规则适用性、条件推导分别记录；模型核验不是人工确认。
5. 行动：actor 首步、实际选择修改、再次改回、真实提交、原评分、超时/失败。
6. 成本：每方案及总请求尝试、tokens、浏览器操作，包括任何失败和重放。

“多了一条候选”“出现了正确行动标签”“生成了忠实的候选 O/B/C”“最终真实提交正确”是不同进展，不应用同一个成功标签。

## 8. 迁移例与本轮停止点

pub013 / b002 可以先固定并准备为后续迁移开发检查；它们都曾用于本研究开发，不是 holdout。只有在明确固定图条件、输入状态、方案与新增预算安排后才实际运行，不能看到 pub001 成功便仅挑看起来最易成功的版本。

它们最多说明提示没有直接写死 pub001 的实体或答案，以及在不同图形/任务上可执行；不能证明通用性。即便迁移不理想，也不得回看其 gold 后逐例改提示。

当前建议结论：修订后的三方案面板可以执行；可接受的终点既包括有证据支持的进展，也包括三方案全部失败。预算到达或预定面板结束后停止，不能以“最终一定成功”为理由继续无界搜索或掩盖旧失败。

## 增补审查：逐行动独立调用的后备 V4

主执行者在真实执行前又提出：不提供旧候选，对每个公开选项对称调用一次候选生成，每项只作为假设，允许空结果；合并所有输出及旧链后使用共同核验/actor。此提议尚未执行。

判断：该设计仍在“发现更多解释”的研究范围内，不天然制造假竞争；但已是**按行动分解的假设条件生成**，不再是仅改反问文本的对照。

优先建议在运行前把它与前三方案一起固定，两 arm 均执行；若保留为后备，应在执行前明确触发规则，并保存决定继续研究的离线审查依据。研究者根据开发结果决定另跑固定方案，不等于把答案交给在线模型；但这种适应性开发不能包装成独立预注册验证。

额外边界：

- 包含当前选择在内的每个公开选项都调用，顺序预先固定，不只测研究者认为正确的选项。
- 对每项允许空候选；不能把“假设该项就是最符合任务的对象”当作 B，也不能为成立而改任务目标。具体图面观察必须另行记录，随后接受核验。
- 全部原始输出保留，包括没有支持、相互冲突、重复和循环论证；Codex不筛掉不利候选后再交 actor。去重只能使用事先声明的确定性规则并保存被合并记录。
- 记录新增行动标签与新增解释依据的区别；每选项一条记录不是三条有效竞争解释的保证。
- 逐项额外调用的预算和错误机会是方法的一部分。若比全局搜索更好，首先只能归因整个分解方案，不能单独证明全局模型“过早认为已覆盖”就是因果机制。
- 该方案仍看到真实当前选择、历史和选中控件，不能称无行动锚定。
- 总预算不增加；若发生重试导致面板未完成，保留未运行部分，不能隐形重置账本。V4 的 schema 候选数量、ID 去重、核验覆盖必须离线验证，不可通过丢弃链来适配旧限额。
