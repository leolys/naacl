# 通用反问驱动竞争解释：有界开发方案

日期：2026-09-25。依据用户本轮 goal 请求及 6 样本 / 24 次请求尝试 / 3 美元估算上限授权。本方案不覆盖旧结果，不扩大到 140 条。

## Problem Anchor

- 底线问题：在没有执行报错时，发现并修正缺少充分可见证据支持的待提交决策。
- 本轮瓶颈：反问停留在抽象来源／时效条件，未把当前结论所依赖的可见事实与解释桥梁变成能由同图证据检验的竞争命题。
- 非目标：不强制反向答案、不把打印文字或惯常几何设为真值、不开发观察选择器、前提账本、长程回滚或持久状态新机制；不宣称论文新颖性或完整 Agent 防御效果。
- 约束：同一完整原图和公开任务；O 只记录可见事实，B 才进行解码；隐藏答案、另一 arm、误导类别、人工框定冲突区域均不进入模型；旧工件只读。
- 成功条件：模型自行形成有图内动机、与原链在解释关系上有实质差异且可区分的竞争记录；允许同答案、仅反驳原依据或无法确定；不能把更多候选、换答案或结构通过本身算成功。

## 技术缺口与最小路线

本地依据为 METHOD_SOURCE.md §3.2—3.3、2026-09-25 b001 的真实三步记录。旧提示已要求不同解释，但没有操作性地要求重新核对可见标记、文字和连接二者的桥梁；三个问题都偏向来源／当前性，新链只是原条件的改写。只有这一个开发现象，不能断言提示是唯一原因，亦不能否定普通整图重读。

路线 A（采用）：在既有反问调用中增加短的视觉事实清点，并让每个反问暴露“当前桥梁—候选桥梁—区分它们的可见依据”；保留随后独立候选与核验两调用。路线 B（不采用）：再加独立观察 agent、多尺度裁剪、搜索控制器或训练；在没有 A 的残余证据前不增加复杂度。

## 方法与接口

完整原图 + 公开任务 + 继承原论证 → 反问（同一次调用内：少量原始观察 + 三个相连问题） → 新候选 0–2 条 → 新旧候选同图核验。

反问应先清点与任务比较有关的可见标记、文字和映射线索，不只复述原链已有文字，不先判断冲突存在。观察中允许“位置较低、颜色较浅、可见长度较长”等画面比较；数值/风险/增长排名和商业含义属于 B/C。对同一对象与范围，判断原链的解释是否遗漏了可见关系；若出现不一致，把它定位到实体绑定、编码映射、比较范围或充分性，而不是泛称图不可信。

三个问题仍对应观察是否充分、解释规则是否适用、是否存在另一解释。不规定必须找到哪一种冲突。候选必须回应真实生成的问题，不由执行 Codex 补写。来源／时间问题并非禁用：仅在公开任务确实有相关未满足条件或图内出现具体线索时，才能作为有实质差异的竞争依据；缺少日期本身不自动推翻公开任务已指定的图表。

实质差异用简短记录说明：原桥梁是什么、新桥梁是什么、什么可见事实会令两者作出不同判断、这种不同如何影响结论支持。两种假设都可以未确定。没有可区分变化的改写不能计作竞争成功；程序只能验证字段与引用，不能替代语义审核。

新增必要接口修正：旧 schema 要求每条链必须支持一个表单选项，但论文允许仅反驳当前依据。新版本允许 `claim_kind=challenges_support|underdetermined` 且 `option_label=null`；这不等于选择 null、不产生浏览器动作。支持具体行动的链仍只能使用完整公开选项。保持旧 runner/normalizer 不变，本轮另存接口版本。

核验器仅收到完整原图、公开任务和规范化论证，不收到哪条为原链、questioner 身份/评语、旧核验 verdict 或 gold。分别核验 O、B、推导。规则状态只是本次核验的快照，不做跨步记忆或行动提交。未解决冲突不由多数票、重复次数或默认文字权威解决。

## 复杂度与训练

冻结现有模型、图像输入、API 客户端和预算机制。新内容只有反问/候选提示及容纳非行动结论的接口；不训练、不增加 GPU、不启用浏览器。三调用完成一例，与上一轮相同阶段数。不得把这一提示诊断包装成已证明的新机制。

## 最小验证（最多三个块）

1. 工程离线检查：原输入隔离、问题实际传递、候选来源绑定、空竞争允许、非行动反驳保留、核验来源隔离、预算和失败不重采样。mock 只证明链路。
2. 预先固定最多六例：b001 为已知开发例；跨其他原任务使用同一固定提示。选择依据为预定 ID 与公开资产可用性，不能据本轮模型结果更换；所有 140 例已有生成史，不称任何一例严格未见集。优先加入未修改的原 clean 图作为无冲突控制（若资产不可用，明确缺失，不制造图）。每例只跑一次三阶段，余预算只用于允许的传输重试。
3. 事后独立审查：原始反问是否确有图内依据、O 是否混入解读、新链是否实质不同、条件是否可区分、冲突是否仅声称而未读到，以及干净图上是否制造虚假竞争。Codex 审查不是人工确认或模型能力 gold。

结果分层：工程完成；提出针对图内桥梁的反问；有实质竞争；竞争通过/未通过/未确定；推荐保持/改变/空；无网页行动。旧 b001 仅历史参照，无调用数匹配消融，不将差异因果归给某句话。若面板没有显式 clean 控制或结果仍不足，就报告证据缺口；不循环调参到 PASS。
