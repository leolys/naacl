# 本轮 goal 与预先固定协议

目标是让反问产生有实际视觉依据、解释关系不同且可检验的竞争链，而非必然反向选择。工程成功、候选质量、视觉正确性和行动纠错分别报告。

## 数据与证据权限

五个开发暴露基础任务、六个静态条件单元，按 manifest 固定。只有 b001 增加一个原有 clean 条件。不称六个独立任务或未见泛化集。选择依据为指定开发例及各目录第一个 ID 的公开图表形态，不查看本轮结果挑选。pub001 与 pub013 同为地图，在六例额度内保留已知 O/B 边界开发例 pub013。

五个 original 单元仅继承原初始选择及原生成顺序中第一条支持该选择的链、其引用规则；不继承其余旧竞争链与核验结论。不按旧 score 选择起点。原链有可能已经写出某个冲突，因此结果必须区分“起点已明说”“反问新注意到”；发现与追问不能混算。clean 独立生成一条起点论证，不从另一条件迁移 chain、proposal、问题或结论。clean/public 文本与 original 经公开 HTML 提取比较一致，但图像、尺寸和起点来源不同，不能将其当作严格只改变图像的受控效应。

## 固定调用链

同图公开输入 + 起点 OBC → 一次反问（少量原始视觉事实，三个相连问题）→ 一次候选（0–2 条）→ 一次核验。

全例使用相同 prompts_v2.py，无任务 ID 路由、品牌词、特定数字或示范冲突。三个问题始终围绕观察充分性、规则适用性、替代解释，不预先规定应否存在冲突。只提出泛泛来源／时效谨慎而没有实际任务相关区别，不能计为有力竞争；确有公开时效约束时仍可质疑。

核验器不接收来源身份与 critic 摘要。O 与 evidence.content 只能是直接可见内容；编码方向、数值解码、排序和任务意义在 B/C。新的 `claim_kind` 允许只反驳当前依据或保留未确定，不强迫挑选另一行动。规则状态只是核验判断的快照，不等于真值、人工确认或跨步稳定恢复。

## 前置验收与停止

审查者先检查通用性和定制化风险；独立工程审查与阻断网络的离线测试先通过。真实调用前固定版本。执行阶段不修改提示，不因语义或格式不理想补跑，不引入新的费用或 GPU。

已有 APIYI / gpt-5.6-terra（网关别名）、temperature 0、原图完整输入、每阶段最多 3800 tokens。19 次计划调用，含 clean 初始链 1 次；24 次总请求尝试、3 美元估算上限、串行，无额外翻译 API。继承旧调用另记来源不计新用量；重试和失败全计入新账本。估算单价沿用原本地账本代理值，不是已验证现价或实际账单。仅明确的传输拒绝可重试；已发送结果未知时停止。

## 预定义阅读口径

逐例展示起点、真实三个反问、真实新增链、核验证据/状态与推荐。记录：是否定位有依据的视觉关系、是否纯观察、是否实质不同、是否能区分、是否臆造冲突、是否仅改了措辞。生成器与核验器的“支持”只是模型判断；原生 Codex 质检单列，不冒充人工审核或隐藏真值评分。

强解释生成信号：b001 上能提出真实图内动机的不同解释；且至少一个非 b001 图表类型上出现有证据的桥梁追问，而 clean 不凭空声称冲突。这个小面板仍不能证明提示改动的因果效应、稳定跨样本率或完整方法有效。若未达到，就明确不足，不反复追加直到成功。

## 审查后固定的归因要求

本提示是 development-informed bridge audit：受旧 b001 失败启发，但没有注入 b001 品牌、数字、具体冲突位置或答案。不能称为无开发先验的发现器。

候选的阅读层标签为 `seed_exposed`（同一问题已出现在传给模型的起点）、`newly_surfaced_relative_to_seed`（相对起点新增图内问题）、`no_grounded_issue`（缺少图内动机）；标签由事后原生 Codex 审阅，不由生成器自述确定，也不是人工 gold。b002 起点规则已有“打印百分比而非柱高”的条件，已预先确定存在 seed 暴露；不能把该区别的新链计为首次发现。

已有观察可复用，不要求清点必须新增事实。非空替代映射需要局部正向线索；已实例化的常规图表语法也可作为可反驳证据。纯支持缺口允许 alternative_reading=null，不伪造替代映射。公开时间/来源/范围要求确实未获满足时，仍可保留未确定。

本轮无浏览器业务动作、无提交、无持久状态新模块。完成六单元后停止，剩余预算不是调提示许可。
