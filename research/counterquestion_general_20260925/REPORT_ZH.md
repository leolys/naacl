# 通用反问能否生成真正不同的解释？六条件开发实测

**结果概括：本轮已经产生了两条涉及视觉编码差异的行动候选链，而不再只有来源／时效的改写；但还不能说“反问器可靠抓住冲突”，也没有证明纠错成功。** b001 的新候选确实比较了扇区大小与打印百分比，但反问阶段仍把图看错；b002 的追问与新链更连贯，却是在原链已提示“标注还是柱高”的起点上展开。

这是五个基础任务、六个静态条件单元的一次开发诊断。真实调用已停止：18 次请求、无重试，估算 0.6804625 美元，非实际账单。没有网页提交，没有 GPU，没有改图、改答案或修改旧 140 条结果。

> ⚠️ 运行前完成了 sub-agent 的两轮方法审查和工程审查；运行后的语义复核因审查服务额度耗尽未完成。下文“记录”来自真实输出，“本地解读”来自主 Codex 的审阅，不是人工确认或新的独立审查结论。正式研究主张状态为 REVIEW_UNAVAILABLE，不把工程 PASS 当作方法有效。

## 1. Goal 和本轮改动

Goal：通过任务无关的反问要求，让模型把“可见事实如何变成任务判断”的解释关系摆出来；当同图有可见歧义或冲突时，提出有依据、实质不同、能说明区分条件的竞争链。没有这种证据时允许零竞争，不能为了换答案编造解释。

流程保持很小：完整原图与公开任务、原链 → 反问 → 新候选 0–2 条 → 上下文隔离核验。没有裁剪器、搜索控制器、前提账本、回滚或新增持久记忆模块。

| 改动 | 具体要求 | 不允许发生的替代 |
|---|---|---|
| 反问前重看视觉事实 | 同一次调用内清点最多 8 条局部可见事实，已有观察可以复用 | 不能把原结论当新观察，不能为填槽位制造事实 |
| 明确被质疑的解释关系 | 说明当前可见事实通过哪个绑定、映射或比较条件支持结论 | 不能只问所有图都可能存在的“是否过期” |
| 给出区分依据 | 新解释需要局部正向线索，说明哪些可见关系会影响两条解释的支持 | 不能仅凭“也许是反向编码”提出竞争 |
| 保留支持缺口 | 新链可以只证明原依据不足，选项为空；不需要编造另一赢家 | 空选项不等于可执行动作 |
| 分开候选和核验 | 生成器的问题和解释不是事实；核验重新看完整图 | 不靠重复次数、角色或原选择决定可信度 |

O 仍只包含画面关系与文字转录；B 才描述编码含义；C 才推出排名、趋势及行动。例如，“颜色较浅”可以是 O，“风险更高”需要经 B 推出，不能混进 O。

本提示是受开发失败启发的通用检查，不是没有开发先验的方法。所有案例用同一提示，没有 b001 的品牌、具体数字、冲突位置或目标答案示范。下面的案例内容由模型实际生成，不是提示中的例子。

## 3. b001 原图：有实质竞争，但不是反问阶段可靠发现

![b001 原始图表](run/cases/b001_original/chart.jpeg)

公开任务是把欧洲高端零售推广预算分配给当前市场份额最高的品牌，可选 Apple、Others、Xiaomi。原链只引用图上 Apple 45%、Xiaomi 30%、Samsung 15%、Others 10% 的文字，在文字数值代表份额的条件下选 Apple。

### 实际三个反问（中文转述，保留模型错误）

1. 标题与四个文字标注是否足以把这些比例视为本次欧洲市场份额证据？模型主要保留了“图内没有日期”的限制，没有提出替代桥梁。
2. 应否按最大打印比例，而不是颜色或位置确定领先品牌？模型回答：**“文字与扇区面积排序一致，Apple 扇区大于其他扇区。”** 这是模型实际作出的错误观察，不能当已核实事实。它同时写出一个条件检查：若扇区与标注排序相反，原解释支持会减弱。
3. 是否有另一种可见解读使 Apple 不是本次领先者？模型回答没有找到局部依据，候选桥梁为空。

### 候选阶段实际新增的链

| 层 | 新链 n1 的中文内容摘要 |
|---|---|
| O：可见事实 | 带 Others 10% 的红色扇区比带 Apple 45% 的浅橙扇区大；模型还说 Apple 扇区最小、Others 比其余每一块都大 |
| B：解释条件 | 如果面积／角度而不是扇区内文字代表市场份额，面积最大的品牌才是领先者；采用此规则需要确认几何编码在当前图适用 |
| C：条件性结论 | 在这种面积编码解释下选 Others；这与文字数值导出的 Apple 解释不一致，尚需判断哪种编码有依据 |
| 区分检查 | 比较各标注与所在扇区的对应：若按比例绘制，45% 那块应大于 10% 那块，而当前图不是这样 |

新链确实在实际 API 调用中接收了三个反问，并链接 q1/q2/q3；但问题阶段没有正确识别冲突，是候选调用重新看图后提出了它。因此，“问题被传递”不等于“问题已正确发现”，也不能证明反问的因果增益。

### 核验与规则状态

规范化后新链为 c1/r1，原链为 c2/r2。核验器承认 Apple 与 Others 的文字—几何冲突；对原链给出 O 支持、B 未确定、推导未确定。对新链给出 O 反驳、B 未确定、推导反驳，理由是它认为 Others 与 Xiaomi、Samsung 的扇区大小近似，未唯一最大。模型最终无推荐，两条规则状态均为待核验（pending）。

本地解读：图上 Others 扇区大于 Apple 的关系可直接比较，构成真正的竞争动机；但“Others 必然是全局最大并应获预算”是更强结论，不能由前一个局部比较自动推出。核验器对三个大扇区的判读本身也不能当真值。本例没有确认替代答案，也没有行动纠错。

归因：相对输入的原链，几何—文字问题是在候选阶段新出现；反问阶段的错误几何观察仍是明确残余。

## 4. b001 clean：同一提示没有硬造竞争

![b001 未修改的原 clean 图](run/cases/b001_clean_control/chart.png)

模型只看此图和相同公开任务，先独立生成 Apple 链。三个问题分别检查标题与标注的任务范围、最大份额到选项的对应、45% 是否可能绑定别的实体。模型判断标注与几何一致，没有局部替代线索，三个 candidate_bridge 均为空。

这是一个有用的单例 sanity 现象，但不是低误报率证据：只有一个 clean 条件，且 clean 与 original 起点生成方式及图像尺寸不同，不能作严格因果比较。

## 5. b002：反问与新链连贯，但冲突维度已在起点中

![b002 原始图表](run/cases/b002_original/chart.jpeg)

公开任务要求把使用份额最高的浏览器分配到优先兼容性测试队列。原链按 Edge 上方 87%、Firefox 上方 23%、Chrome 上方 5% 选择 Edge；其规则范围已写明“假设标注而非柱高为数值依据”。

### 反问与新链

三个问题都抓住同一可见差异：Firefox 柱顶高于 Edge，但柱上文字是 Edge 87%、Firefox 23%。它们分别问：文字是否足够；为什么标注应优先于共用轴上的柱高；如果柱高代表份额，是否会改选 Firefox？

新链 n1 的 O 为柱顶位置、共同基线、0–100 轴、浏览器名称与文字标注。B 是“如果标题所指使用份额由共轴柱高编码，则柱最高者份额最大”；C 为在此条件下选 Firefox。区分要求是找出能确定哪种编码代表份额的可见说明；模型记录该说明当前不可用。

核验器对新旧链的 O 均支持，B 和推导均未确定，最终无推荐；m1/m2 均 pending。

本地解读：这里不是泛泛来源谨慎，而是同图中两个解读关系的实质区别；但它只能展示“对已提示的解释维度进行具体比较”，不能当作没有起点提示时的新发现。发现不一致与确定正确答案仍是两步。

## 6. env001：支持缺口有记录，核验因接口问题未运行

![env001 原始图表](run/cases/env001_original/chart.jpeg)

公开任务要求判断 2005–2014 的温度变化是否足够显著以进入专项后续处理，还是留在常规监测。原链用端点文字 23.9°C 与 10.1°C 计算 13.8°C 下降，并条件性地把它视为显著变化。

三个反问分别检查端点绑定、何种阈值把变化映射到显著/普通、标注同时出现美元符号与 °C 是否造成含义问题。生成器最终没有采用美元单位解释，只生成一个支持缺口：端点差异本身不能代替公开任务未说明的分类标准。选项为 null，没有编造反向动作。

但新链在 observations 里同时放入 chart_1 引用和 `task_048` 的公开任务文字引用。当前 O 接口只允许 chart_1；后者虽来自已经提供的公开任务，却不是允许的证据格式，因此 validator 拒绝该候选，未调用核验器。**不是 API 不可用，不是核验失败，也不是成功纠错。** 原始文本完整保留，没有改成合格格式后重跑。

本地解读：阈值问题主要是任务语义支持缺口，且原链本就有“如果视为显著”的条件，不应算成新的关键视觉冲突发现。图中不等距刻度这一可见关系没有成为实际问题或候选的焦点；不能把泛化目标说成已全面覆盖。

## 7. health001：有新的支持质疑，也有证据和编号风险

![health001 原始图表](run/cases/health001_original/chart.png)

公开任务要求选择年度死亡监测中需作峰值后续处理的年份，可选 2018、2010 或方法参考审查。原链已读取 Count 刻度向下增大，并认为 2018 点略低于 2017，因而选 2018。

### 反问与两条非行动候选

反问 q1/q3 认为 2017、2018 点看起来接近同高，问是否足以证明“唯一 2018 峰值”；q2 指出标题写 Mortality rate，而轴写 Count。新候选为：

- n1：O 记录末两点“看起来同高”；B 要求有可分辨的差异才能支持唯一 2018 峰值；C 是依据不足，非另一年份选择。
- n2：O 记录标题/轴用词不同；B 要求澄清数量还是比率；C 仅质疑原规则的 Count 描述，不声称改变峰值年份。

本地解读：末两点非常接近，允许表达难以分辨，但不能把“看起来接近”自动升级为数学相等。公开选项也没有明确写“唯一”；把严格唯一性添加为行动必要条件，需要额外论证。数量/比率用词差异确实可见，却不自动改变同一已绘序列中哪个年份最高。两条候选都不能直接算有效纠错。

### 确认的接口污染：正文中的 r1 没有随编号重排

新候选 n2 在规则范围和结论正文里写了“r1 的 Count 断言”，此时 r1 指输入的原规则。程序排序后：原规则变为 r3，新 n1 规则变为 r1，新 n2 为 r2；结构化 rule_id 正确重排，但正文里的字符串 r1 原样保留。

核验器于是说“r1 是几何唯一性规则，没有 Count 断言”，据此把 n2 的 B 和推导标为反驳。这与实际请求中的编号错指直接吻合。该条核验受接口污染，不能当模型成功识别无效规则的证据。

实际状态记录仍照原输出保留：m1 active（n1 的唯一性条件），m2 revoked（n2，受错指影响），m3 pending（原规则），最终无推荐。本轮没有修写真实结果，没有在发现后补跑。

## 8. pub013：遵循已有图例，不为竞争而反转

![pub013 原始图表](run/cases/pub013_original/chart.jpeg)

原链已把 O 与 B 分开：O 是 Illinois 浅黄、Kansas 深红、Delaware 橙色，以及图例顶端浅黄旁写 High/100、底端深红旁写 Low/0；B 才将这些颜色对应到风险排序，C 才选择 Illinois。

三个问题检查三州是否在同一图例中可比、图例端点与地图颜色的对应、是否另有指标/图例/范围。模型没有找到有局部依据的另一种映射，返回零竞争；核验保持 Illinois，m1 active。

本地解读：这符合“没有充分竞争依据就不硬造”的设计；不能因未生成反向深色解释而判失败。实际图例关系本就存在于原链，亦不能据此主张反问新发现了它。

## 9. 对目标的回答

本轮显示了一个较上次更有内容的流程输出：b001 的候选阶段、b002 的反问和候选阶段产生了可定位的视觉编码竞争；clean 与已有图例解释完整的 pub013 允许无竞争。这满足了“流程可以实际生成不同解释，而非只改写来源条件”的开发观察。

但更强的目标尚未得到确认：

1. b001 反问器仍把原几何看错；真正冲突由后续候选调用指出，不能归功于准确反问。
2. b002 已有 seed 提示，未证明跨任务自主发现。
3. health001 的质疑可能过度要求唯一性，且至少一条核验被正文编号错指污染。
4. env001 没完成核验；有任务语义缺口不等于发现关键视觉关系。
5. 没有同时的旧提示对照，没有人工核验，也没有网页完成率或持续纠错结果。

因此，不把本轮写成“方法已通用有效”或“已解决误导图表”。更合适的结论是：**生成端已有实质竞争的开发信号，但反问定位、观察正确性和核验接口仍是残余问题。** 正式结果到研究主张的审查状态仍是 REVIEW_UNAVAILABLE。
