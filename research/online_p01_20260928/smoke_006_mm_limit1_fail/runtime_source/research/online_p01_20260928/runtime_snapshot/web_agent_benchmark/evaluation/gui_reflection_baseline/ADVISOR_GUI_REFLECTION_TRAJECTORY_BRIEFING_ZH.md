# GUI-Reflection 在误导可视化任务中的轨迹差异：汇报版

日期：2026-09-01  
用途：面向导师汇报代表样本、纠错作用位置、失效边界与后续研究问题。

## 一句话结论

GUI-Reflection 并非完全无效：它有时能让智能体返回上一页，有时还能改选正确动作；但现有轨迹纠错没有稳定地完成下面这条完整恢复链：

```text
收到错误或矛盾信号
    → 返回可修改页面
    → 撤销产生旧动作的视觉判断
    → 根据图表重新形成判断
    → 把新判断绑定到正确按钮
    → 点击确认并产生真实提交
```

三个代表样本恰好暴露出三个不同断点：

| 代表样本 | 返回上一页 | 撤销旧视觉判断 | 改选正确动作 | 真实确认提交 | GUI-Reflection 实际作用到哪里 |
|---|---:|---:|---:|---:|---|
| 城镇游客趋势（`pub010`，误导标题） | 否 | 否 | 否 | 错误提交或超时 | 看到了矛盾提示，但误导标题仍支撑旧判断 |
| 可再生能源贡献（`env008`，柱高与标注值冲突） | 是 | 否 | 否 | 否 | 完成了局部导航撤销，随后重新进入同一错误实体 |
| 工厂产量趋势（`b035`，误导标题） | 是 | 是 | 是 | 否 | 完成了语义纠正，但把“已经选中”误当成“已经提交” |
| 城镇游客趋势的正常标题对照 | 是 | 是 | 是 | 是（保留最近轨迹历史时） | 证明矛盾提示和返回界面本身是可执行的 |

因此，最准确的研究表述是：**GUI-Reflection 能提供程序性的轨迹推进，但视觉前提撤销、正确动作重绑定和最终提交仍是彼此独立的失败点。**

## 这版实验跑了多少数据

### 先说明“数据量”的统计单位

这里需要区分三个数字，不能把它们混成一个样本量：

- **基础任务数**：数据集中语义不同的原始任务；这是最接近独立样本数量的单位。
- **运行次数**：一个固定任务、布局和实验条件组合形成一个运行目录；一个运行可以包含两条或四条轨迹。
- **轨迹数**：一个模型在一个明确条件下从初始页面运行到提交、超时或宣称完成，实验文件中称为一个 cell。布局轮换和历史条件会增加轨迹数，但不会增加基础任务数。

### 本轮正式扩展实验

本轮正式扩展实验从我们的 `benchmark_v2_open` 数据集和其中的 `strict_review94` 子集中选取了 **8 个基础任务**，形成 **16 个完整运行、54 条模型轨迹**。

| 基础任务 | 图表与误导类型 | 正式运行数 | 模型轨迹数 | 在实验中的用途 |
|---|---|---:|---:|---|
| 城镇游客趋势 `pub010` | 折线图；错误标题声称下降，但数据总体上升 | 7 | 28 | 最强的同渲染误导与恢复失败样本；包含三个按钮布局 |
| 工厂产量趋势 `b035` | 折线图；错误标题声称上升，但数据总体下降 | 3 | 12 | 语义恢复成功、最终确认失败的部分正例 |
| 公司季度收入 `b038` | 折线图；错误标题声称稳定，但数据总体上升 | 1 | 4 | 同渲染后正常版本能力不成立，因此作为排除样本 |
| 业务散点图 `b008` | 散点图；视觉比例失真 | 1 | 2 | 只跑正常版本，用于检查基础能力 |
| 环境构成 `env003` | 饼图；不适当的尺度函数 | 1 | 2 | 只跑正常版本，用于检查基础能力 |
| 公共统计地图 `pub012` | 分级设色地图；图例方向反转 | 1 | 2 | 只跑正常版本，用于检查基础能力 |
| 公共统计聚合 `pub009` | 堆叠图；截断尺度与阈值聚合共同误导 | 1 | 2 | 只跑正常版本，用于检查基础能力 |
| 环境均值计算 `env025` | 错误平均值标注与算术判断 | 1 | 2 | 只跑正常版本，用于检查基础能力 |
| **合计** | **8 个基础任务** | **16** | **54** | 不把重复布局或历史条件当成独立样本 |

54 条轨迹可以按实验用途进一步拆成：

- **同渲染标题干预与恢复测试：44 条。**来自 `pub010`、`b035`、`b038` 三个折线图任务。正常和误导版本由同一份数据重新绘制，除标题文字外保持一致。
- **复杂图表正常版本能力筛选：10 条。**来自另外五种非标题误导类型，每个任务只跑“单次作答”和“允许复查”两条正常版本轨迹。由于正常版本都没有达到端到端正确，对应误导版本没有继续运行。

正式实验前还运行了 9 个候选任务的校准轨迹，用于发现原始图片配对泄漏、正常版本能力不足和运行器不支持的动作。这些校准数据没有进入上面的 16 个正式运行，也没有进入结果分母。

### 能源柱状图的机制开发面板

汇报中的可再生能源样本 `env008` 来自前一阶段单独冻结的机制实验。它是 **1 个基础任务、1 个正式开发运行、50 条机制轨迹**，具体包括：

| 机制测试 | 轨迹数 | 测试问题 |
|---|---:|---|
| 不同记忆提示 | 8 | “不要重复旧动作”或“重新核对印刷数值”能否阻止旧分支重入 |
| 当前截图与最近轨迹历史对比 | 6 | 最近截图和动作历史究竟帮助导航推进，还是帮助语义纠正 |
| 实体角色、按钮位置和颜色轮换 | 24 | 模型跟随的是正确角色、页面位置，还是固定的 Wind 实体 |
| 最终确认历史探针 | 12 | 最近历史是否只促使模型确认当前选择，而不检查选择是否正确 |
| **合计** | **50** | 同一个基础任务的机制变体，不是 50 个独立任务 |

因此，整份汇报展示的实验产物可以说是 **9 个基础任务、17 个正式运行目录、104 条被执行的模型轨迹**；但论文统计时必须分别报告“54 条多任务扩展轨迹”和“50 条单样本机制轨迹”，不能把 104 当成独立样本数量，也不能计算一个统一成功率。

### 轨迹产物是否完整

本轮 54 条扩展轨迹共产生：

| 产物 | 数量 | 审计结果 |
|---|---:|---|
| 模型动作步骤 | 199 | 请求和响应标识均唯一 |
| 网页状态事件 | 191 | 能与动作步骤和页面状态连接 |
| 截图 | 223 | 199 张模型步骤截图，加 24 张评测器干预截图；文件哈希全部一致 |
| 真实提交 | 34 | 每次都能连接到页面事务和隐藏评分记录 |
| 结果矛盾验证记录 | 26 | 所属任务、选项、位置和结果均能重新核对 |

独立红队没有在正式纳入的 16 个运行、54 条轨迹中发现产物完整性错误。能源样本的 50 条轨迹也全部执行完成，但它被协议明确限定为单样本开发面板。

| 类型 | 基础任务数 | 本轮如何使用 | 能回答的问题 |

| 饼图尺度函数不当 | 1 | 只跑正常版本能力筛选 | 同上 |
| 地图图例方向反转 | 1 | 只跑正常版本能力筛选 | 同上 |

## 实验是如何设置的

### 1. 同渲染视觉控制

`pub010`、`b035`、`b038` 的正常和误导图片都从同一份原始数据重新绘制为 1000×750 图片。画布、字体、坐标轴、刻度、数据折线、颜色和边距完全相同，只允许标题文字不同。

逐像素检查结果为：

| 任务 | 两图不同的像素数 | 标题区域外的不同像素数 |
|---|---:|---:|
| `pub010` | 8,494 | 0 |
| `b035` | 7,527 | 0 |
| `b038` | 6,239 | 0 |

因此，`pub010` 和 `b035` 的正常—误导差异可以解释为标题干预，而不是 JPEG 压缩、尺寸、字体或布局同时变化。

### 2. 三类任务流程

每条主要轨迹属于下面一种完整条件：

1. **单次作答**：看到图表后选择一个操作并直接提交，不提供修改机会。
2. **普通复查**：选择后进入复查页，模型可以确认或者返回修改，但页面不告诉它当前选择是否正确。
3. **显式结果矛盾下的定向恢复**：评测器先在真实网页中放入一个错误选择，随后重置模型历史，并显示“当前选择与另一个已验证结果冲突”。页面不泄露正确按钮，模型需要自行决定是否返回和改选。

另有一个无矛盾提示的继承错误对照：评测器同样放入错误选择，但只要求普通复查，不告诉模型存在结果冲突。它用于判断行为变化究竟来自纠错信号，还是仅来自进入复查页面。

### 3. 历史输入对照

在继承错误实验中使用同一个模型权重比较两种输入：

- **最近完整轨迹历史**：最多保留最近四张截图、点击位置标注和完整动作描述历史；
- **只给当前截图**：清空最近截图、动作历史和记忆，只提供当前页面。

这个对照测量历史信息如何改变恢复行为。它不是两个不同模型，也不是“训练了反思”和“没有训练反思”的比较。

### 4. 布局和位置控制

游客趋势任务使用三个不向模型暴露角色的按钮布局，使正确按钮、误导按钮和中性按钮分别轮换到三个位置。三种布局中图表和任务文字不变，用于排除模型只记住固定按钮位置。工厂产量和公司收入使用标准布局。

### 5. 样本准入规则

一个样本必须先满足“正常版本的单次作答和普通复查都产生正确真实提交”，才允许把误导版本的失败解释成恢复失败。

- `pub010` 和 `b035` 通过正常版本能力检查，因此进入定向恢复分析。
- `b038` 在同渲染后正常版本失败，因此停止后续恢复实验。
- 五个复杂图表的正常版本共 10 条轨迹、0 条任务成功，因此对应误导版本没有运行。

### 6. 恢复结果分层记录

我们不把一次返回直接算成恢复成功，而是依次记录：

```text
第一次选择了什么
    → 是否看到了复查或矛盾提示
    → 是否真实返回到可修改页面
    → 返回后选择了什么
    → 是否重新进入旧错误分支
    → 是否点击确认
    → 网页是否产生真实提交回执
    → 隐藏评分器是否判定正确
```

模型输出“任务完成”本身不计成功；必须存在网页提交事务和隐藏评分记录。每条轨迹最多执行 8 个模型步骤，超出后记为“在该步数预算内未提交”，而不是声称模型永远不会恢复。

### 7. 网页和执行环境

| 设置项 | 实际设置 |
|---|---|
| 浏览器执行后端 | Selenium + Firefox |
| 浏览器视口 | 1280×960 |
| 图表受控渲染尺寸 | 1000×750 |
| 每条轨迹最大模型步骤 | 8 |
| 模型状态 | 每条轨迹开始前调用官方 reset，清空动作、截图历史和记忆 |
| 页面操作 | 模型输出点击坐标、返回、等待、记忆或任务结束等官方动作；执行器记录真实页面回执 |
| 评分 | 正确动作加真实确认提交；只选对但未确认仍为失败 |

## Agent 背后的模型与参数

### 模型身份

本实验没有调用 GPT、Claude 或其他闭源 API。所有轨迹都由 GUI-Reflection 官方发布的本地模型驱动：

| 项目 | 实际值 |
|---|---|
| 官方模型 | `craigwu/GUI_Reflection_8b_SFT` |
| 阶段含义 | GUI-Reflection 最终监督微调模型；名称中的 SFT 指 supervised fine-tuning，即监督微调 |
| 本次固定 checkpoint | `720d6239d18215417a80ac49f444a6145e073e9c` |
| 官方规模标记 | 约 8B 参数 |
| 本地权重 | 4 个 safetensors 分片，总张量文件大小 16,150,583,296 字节，以 bfloat16 加载 |
| Agent 实现 | 官方仓库中的 `GUI_Reflection_Agent`，没有替换为我们自己写的决策模型 |
| 是否重新训练 | 否；本实验只复现官方 checkpoint 推理，没有进行额外微调 |

### 多模态模型架构

GUI-Reflection 8B 不是纯语言模型，而是基于 InternVL 的视觉语言模型：

| 组成部分 | 配置 |
|---|---|
| 总体架构 | `InternVLChatModel` |
| 语言模型 | InternLM2.5-7B-Chat，对应 `InternLM2ForCausalLM` |
| 语言层数 | 32 层 |
| 语言隐藏维度 | 4096 |
| 前馈网络维度 | 14,336 |
| 查询注意力头 | 32 |
| 键值注意力头 | 8 |
| 词表大小 | 92,544 |
| 最大位置长度 | 32,768 token |
| 视觉编码器 | `InternVisionModel` |
| 视觉层数 | 24 层 |
| 视觉隐藏维度 | 1024 |
| 视觉注意力头 | 16 |
| 图像 patch 大小 | 14×14 |
| 基础视觉输入尺寸 | 448×448 |
| 动态图像切块 | 最少 1 块、最多 12 块，并启用缩略图 |

### GUI-Reflection 的历史和提示输入

官方 Agent 在每一步接收：

- 当前 1280×960 网页截图；
- 最多四张过去截图，历史截图缩放为 448×448；
- 历史点击截图上的点击位置标注；
- 从该轨迹开始以来的完整动作及动作描述；
- 模型通过 `MEMORIZE` 动作主动写入的 memory；每条新轨迹开始时 memory 为空；
- 当前任务指令和官方 GUI 动作空间。

模型被要求按“思考过程—动作描述—下一动作”格式输出。我们没有在失败后人工修改模型自然语言，也没有在解析失败时用数据集真值补出正确动作。

### 推理解码参数

所有正式轨迹使用相同的确定性解码设置：

| 参数 | 数值 | 含义 |
|---|---:|---|
| `max_new_tokens` | 1024 | 单步最多生成 1024 个新 token |
| `do_sample` | false | 不进行随机采样 |
| `temperature` | 0.0 | 与关闭采样共同形成确定性输出 |
| `top_k` | 0 | 不做 top-k 随机采样 |
| `top_p` | 1.0 | 不做 nucleus 截断 |
| `num_beams` | 1 | 不进行多分支 beam search |
| `repetition_penalty` | 1.0 | 不额外施加重复惩罚 |
| 数值精度 | bfloat16 | 没有使用 8 位或 4 位量化 |

这里的布局重复是确定性复现，不是从同一随机分布中重复采样多条 rollout；因此不能把三个布局当成随机独立试验计算置信区间。

### 软件和硬件

| 项目 | 实际环境 |
|---|---|
| GPU | NVIDIA H100 80GB HBM3，使用物理 GPU 7 |
| PyTorch | 2.8.0 + CUDA 12.8 |
| Transformers | 4.37.2 |
| 权重精度 | bfloat16 |
| 注意力实现 | checkpoint 配置请求 FlashAttention 2，但运行环境中的扩展不可用；日志确认实际回退为 eager attention |

## 全部实验结果总览

| 数据部分 | 关键结果 | 可以得出的结论 |
|---|---|---|
| 游客趋势 `pub010`，自然决策 | 正常标题 6/6 正确提交；误导标题 6/6 提交下降响应 | 只改变标题即可稳定改变第一次决策和最终操作 |
| 游客趋势，显式结果矛盾 | 正常标题 6/6 返回并改选正确；误导标题 0/6 返回、0/6 改选正确 | 同一矛盾信号可执行，但未能覆盖误导标题建立的旧前提 |
| 工厂产量 `b035`，自然决策 | 正常标题 2/2 正确；误导标题 2/2 选择中性监控并错误提交 | 标题冲突破坏正确动作绑定，但不是精确陷阱跟随 |
| 工厂产量，显式结果矛盾 | 4/4 返回并改选正确，只有 1/4 形成正确真实提交 | 语义恢复与端到端提交之间仍有断点 |
| 公司收入 `b038` | 同渲染正常标题 0/2 正确 | 不满足恢复实验的正常版本能力前提，排除 |
| 五个复杂图表正常版本 | 10 条轨迹、0 条任务成功 | 当前 checkpoint 存在基础能力下限，不能归因成恢复失败 |
| 能源柱状图 `env008` | 38 条有恢复机会的轨迹中 0 条完成任务；重点的 22 条最近历史轨迹中 21 条返回、0 条正确提交 | 返回很稳定，但视觉前提、实体绑定和提交没有随之恢复 |

结果不支持“GUI-Reflection 完全解决”或“GUI-Reflection 完全不起作用”两个极端判断，也不支持报告一个跨类型总体恢复率。它支持的是逐层机制结论：返回、视觉前提修正、正确动作重绑定和真实确认提交必须分别测量。

## 实验条件必须怎样解释

为了避免把内部实验编号当成方法含义，汇报中建议只使用下面三个完整名称。

### 1. 单次作答条件

智能体看到图表与三个操作选项，选择后直接提交，没有返回和重试机会。它回答的是“误导图表能否改变第一次决策”。

### 2. 普通复查条件

仍使用 GUI-Reflection 模型，并保留最近截图和动作历史；智能体选择后进入复查页，可以确认或者返回修改，但页面不告诉它当前选择是对是错。它回答的是“仅靠一般复查流程，模型能否自然发现并纠正错误”。

### 3. 带显式结果矛盾提示的定向恢复条件

评测器先放入一个错误选择，再告诉模型：“该选择与另一个已验证的任务结果冲突。”页面不直接给出正确按钮。模型可以确认、返回或修改选择。

这个条件测量的是：**在外部已经指出存在错误以后，GUI-Reflection 有没有能力执行恢复。**它不测量模型能否自主发现错误，也不能把评测器预置的错误说成模型自己犯下的错误。

另外，我们比较了两种输入历史：一种给模型最近的完整截图和动作轨迹，另一种只给当前截图。两者使用同一个 GUI-Reflection 模型权重，因此不能解释成“训练过反思”和“没有训练反思”之间的模型比较。

## 代表样本一：城镇游客趋势——误导标题使模型拒绝撤销旧前提

### 任务与误导方式

图中游客人数从 1880 年的 993 上升到 1891 年的 2917，净增长 1924。正确中间判断是“总体上升”，正确操作是“选择增长规划并提交”。

两个版本使用完全相同的数据、坐标轴、折线、字号和布局，只改变标题：

| 正常标题版本 | 误导标题版本 |
|---|---|
| ![游客趋势正常标题](runs/expanded_matched_title/pub010/L0/20260831T180601Z_4786f584/cells/candidate_clean/screenshots/step_00.png) | ![游客趋势误导标题](runs/expanded_matched_title/pub010/L0/20260831T180601Z_4786f584/cells/candidate_official/screenshots/step_00.png) |
| 标题写“游客人数上升” | 标题写“游客人数下降”，但折线和数据仍然上升 |

### 没有纠错信号时，误导前后的轨迹

| 图表版本 | 智能体对图表的判断 | 实际轨迹 | 最终结果 |
|---|---|---|---|
| 正常标题 | 总体上升 | 选择增长规划 → 进入复查页 → 点击确认 | 正确提交 |
| 误导标题 | 总体下降 | 选择下降响应 → 进入复查页 → 点击确认 | 错误提交 |

在三个按钮位置轮换布局中，单次作答和普通复查合计得到：正常标题 6/6 正确提交，误导标题 6/6 提交下降响应。普通复查没有让模型自然发现错误，而是让它再次确认了错误分支。

这一步首先证明了真正的误导效应：**只改标题，就能把同一个模型从正确动作稳定推向错误动作。**

### 已明确告知“当前选择有冲突”以后

评测器预先放入错误的“下降响应”，再显示结果冲突提示。正常标题和误导标题下的入口除标题外保持一致：

| 正常标题下的冲突提示 | 误导标题下的冲突提示 |
|---|---|
| ![游客正常标题冲突提示](runs/expanded_inherited_f3/pub010/L0/20260831T181935Z_0fe8c65d/cells/candidate_clean/screenshots/step_00.png) | ![游客误导标题冲突提示](runs/expanded_inherited_f3/pub010/L0/20260831T181935Z_0fe8c65d/cells/candidate_official/screenshots/step_00.png) |

两条代表轨迹发生了完全不同的分叉：

```text
正常标题：
错误的下降响应 + 明确冲突提示
    → 执行返回
    → 重新选择增长规划
    → 点击确认
    → 正确提交

误导标题：
错误的下降响应 + 同样的明确冲突提示
    → 没有返回
    → 再次坚持下降响应
    → 点击确认
    → 错误提交
```

三个卡片布局、两种历史输入下共得到：

- 正常标题：6/6 执行返回，6/6 改为增长规划；保留最近轨迹历史的 3/3 完成正确提交，只给当前截图的 3/3 在最后复查页超时。
- 误导标题：0/6 执行返回，0/6 改为增长规划；保留最近轨迹历史的 3/3 直接确认旧错误，只给当前截图的 3/3 停留到超时。

### GUI-Reflection 在这里起作用到哪里

它并非看不懂“当前选择与结果冲突”这套交互，因为正常标题下能够完整返回、改选和确认。真正的断点是：**当当前截图继续用标题支持“下降”时，外部矛盾没有使旧视觉前提失效。**

可以把模型内部的失败近似描述为：

```text
误导标题：“总体下降”
    → 下降响应是合理的
    → 即使页面说结果冲突，仍优先相信当前可见标题
    → 确认原选择
```

### 起作用或不起作用后的影响

- 正常标题下，轨迹历史帮助模型从正确重选推进到真实确认。
- 误导标题下，同样的最近轨迹历史反而与错误确认同时出现：只有当前截图时模型尚未提交；加入最近轨迹后，它更顺畅地确认了旧错误。
- 因此，历史带来的“更会继续操作”不等于“继续的是正确分支”。

这是一条很强的主论文证据：**局部轨迹延续不能替代视觉前提撤销。**

- [误导标题下确认旧错误](runs/expanded_inherited_f3/pub010/L0/20260831T181935Z_0fe8c65d/cells/candidate_official/steps.jsonl)

任务要求找出贡献最大的能源来源，并把该来源送入优先跟进流程。图中印刷数值是：

- Wind：29.8%，不是最大；
- 但 Wind 的柱子被画得最高，几何高度与印刷数值冲突。

    → 页面仍显示“尚未提交”

### GUI-Reflection 在这里起作用到哪里

GUI-Reflection 确实完成了它训练中最典型的动作：从复查页返回到可修改页面。最近轨迹历史也使模型不再像“只给当前截图”时那样不断重复返回，而是能够继续选择一个选项。

但是，它推进的是旧的 Wind 分支：

- 没有重新枚举 Solar、Wind、Hydroelectric 等印刷数值；
- 没有撤销“最高柱子对应最大贡献”的旧判断；
- 没有把“真实最大值是 Solar”绑定到 Solar 操作卡片；
- 甚至没有完成最终确认。

在记忆提示、历史输入和实体位置轮换三组机制测试中，22 条使用原生最近轨迹历史的轨迹有 21 条完成了有效返回，但只有 4 条表面上选中了正确实体，而且这 4 条都发生在我们把 Wind 轮换成正确答案的合成页面；所有 22 条都没有完成正确提交。在角色轮换的 12 条轨迹里，11 条返回后仍选择 Wind，说明模型锁定的是 Wind 这个实体身份，而不是页面上不断变化的“正确角色”。这些轨迹来自同一个基础样本的机制变体，不能当成 22 个独立任务计算总体比例。

### 起作用后的影响

这里的影响不是“毫无变化”，而是从一种失败变成另一种失败：

```text
只给当前截图：不断返回，无法推进

保留最近轨迹历史：能够返回后继续操作，
                  但继续选择旧的 Wind，随后过早宣称完成
```

因此，这个样本最适合向老师解释：**GUI-Reflection 修复了导航控制，却没有修复从视觉证据到实体、再到操作按钮的语义绑定。**

## 三个样本合在一起说明了什么

### 不是一个“是否会返回”的问题

| 恢复层次 | 游客趋势误导标题 | 能源柱状图 | 工厂产量误导标题 |
|---|---|---|---|
| 识别页面给出的结果冲突 | 没有转化成操作变化 | 是 | 是 |
| 从复查页返回 | 否 | 是 | 是 |
| 撤销旧视觉前提 | 否 | 否 | 是 |
| 重选正确实体或动作 | 否 | 否 | 是 |
| 真实点击确认 | 错误确认或超时 | 否 | 否 |
| 最终性质 | 前提持续支配错误分支 | 只完成导航撤销 | 语义恢复但事务未完成 |

这给出了比“GUI-Reflection 成功率是多少”更有研究价值的机制结论：

1. **最近轨迹历史主要提供程序性连续性。**它帮助模型知道下一步该继续点选或确认，但不会自动验证当前语义是否正确。
2. **返回操作不会自动删除旧前提。**模型可以离开错误页面，却把同一实体或同一趋势判断带回重试页面。
3. **正确重选不会自动变成任务成功。**模型可能把“已经选择正确选项”误当成“已经点击确认并提交”。
4. **误导视觉有时会把反思流程变成错误确认器。**游客趋势样本中，加入最近轨迹后，模型从停留变成了真正提交错误。

## 建议向老师提出的下一研究点

下一方法不应只增加更多“返回后换一个动作”的训练，而应显式保存并更新下面的依赖关系：

```text
图表区域或印刷数值
    → 可检查的中间判断
    → 对应实体
    → 网页操作按钮
    → 是否已产生真实提交
```

收到矛盾提示以后，系统需要依次执行：

1. 标记旧中间判断及其下游动作失效；
2. 回到决定该判断的图表区域重新读取证据；
3. 检查关键类别是否读取完整，而不是只关注一个显著元素；
4. 形成替代判断，并把它重新绑定到网页中的实体或按钮；
5. 在点击确认前检查“新判断—新动作”是否一致；
6. 只有页面出现真实提交状态或系统提交回执才允许结束。

这套方法分别对应三个代表失败：游客趋势需要“旧前提失效”，能源柱状图需要“完整证据读取与实体重绑定”，工厂产量需要“提交状态守卫”。

## 哪些样本不能拿来证明 GUI-Reflection 纠错失败

- `b038` 在同渲染控制后，正常版本本身就没有做对，因此不能把后续失败归因给误导图表或纠错方法。
- 另外五个复杂图表样本在正常版本的 10 条轨迹中没有成功完成任务。这些只能说明当前模型存在基础图表理解或网页操作能力下限，不能作为“GUI-Reflection 无法恢复”的证据。
- 三个按钮布局和两种历史输入是同一样本的重复机制测量，不是更多独立样本；不应把它们包装成总体成功率或显著性统计。
- 带结果矛盾提示的实验使用评测器预置错误，测的是恢复能力，不是自然错误发现能力。

## 五分钟汇报话术

> 我们使用的是 GUI-Reflection 官方发布的约 8B 参数监督微调模型，不是通用闭源 API。它以 InternVL 为多模态架构，语言部分是 InternLM2.5-7B-Chat；每一步能看到当前截图、最多四张历史截图和完整动作历史。推理使用确定性解码，在一张 H100 80GB GPU 上运行。本轮多任务扩展包含 8 个基础任务、16 个完整运行和 54 条轨迹；此外保留一个能源柱状图基础任务的 50 条机制轨迹。后者是同一样本的角色、位置和历史变体，所以我们不把总共 104 条轨迹说成 104 个独立样本，也不报告一个混合成功率。
>
> 我们没有把 GUI-Reflection 简单归类为有效或无效，而是拆开了完整纠错链。第一个游客趋势样本只改了图表标题：正常标题下模型可以在收到矛盾提示后返回、改选并确认；误导标题下，同样的矛盾提示却完全不能让它离开下降响应，说明旧视觉前提没有被撤销。第二个能源样本中，模型确实按训练执行了返回，但返回后又选择同一个 Wind，说明导航撤销没有转化成实体重绑定。第三个工厂产量样本中，模型进一步完成了正确判断和正确重选，却没有点击最终确认，说明语义恢复也不等于端到端任务恢复。三个样本把现有方法的作用边界依次定位在导航、视觉前提与提交状态三个层次，这也直接给出了下一方法的设计：显式记录视觉证据、中间判断、实体、动作和提交状态之间的依赖，并在矛盾出现时成链撤销和重建。

## 审计边界

上述展示来自受控诊断实验。正式纳入的扩展实验共 16 个完整运行、54 条轨迹，截图、动作、评分和验证记录经红队机械复核没有发现完整性错误。能源样本另有 1 个单样本开发运行和 50 条完整机制轨迹。两部分均不能把条件重复当成新的独立任务；这些样本也经过定向筛选，因此结果不应称为已发布基准上的总体恢复率。
