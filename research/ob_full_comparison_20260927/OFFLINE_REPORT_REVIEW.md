## 4. 最终报告前仍需的最小证据检查

### 4.1 账本事件与响应必须唯一且全集对应

目前检查 `(worker, number)` 唯一，但两个不同 number 可以指向同一 `folder + attempt`，使同一响应被计两次；反之，未被账本引用的孤立响应没有全集核对。现有代码逐项 usage 相等也不能排除此类重复记账。

建议只补离线审计，不改线上 runner：

- 对每个已归档响应要求唯一的事件引用；响应相对路径必须无重复。
- 全部已归档响应集合与事件中的实际存在响应集合精确相等；无响应的未知传输/在途事件独立记录，不伪造响应或零用量。
- event 的 worker、version、stage、folder 与真实 owner、固定 assignment 和目录位置相互一致；合法 attempt 范围及序列不因引用同一响应而重复。
- 对可解析原响应比对 HTTP、model 和完整 usage；不把 accepted 的合法性替代其他失败响应的成本核对。

这是正式“实际请求成本已核对”声明的必要条件，不是重新询问模型的理由。

### 4.2 稳定终态身份与展示绑定

CAPTURE_MANIFEST 身份绑定不等于文件之后绝不会变化。最终在同一稳定 capture 上执行完整文件 SHA 审计，再评分/生成展示，并绑定审计与 analysis/HTML 的身份，才能称其为最终证据。不要让另一个未审计 analysis 文件或被修改后的本地原图仅凭相同 manifest 名称替换进去。

当前 `integrity_audit` 对没有 result 的在途单元会跳过阶段全文核对，适合明确标成“已终态范围”的中期审计；最终应要求所有实际存在阶段与账本响应都被覆盖。若受预算、截止时间或未知传输影响无法完整，报告仍保留 140 分母和未完成状态，不通过补发把未知请求变成可解析结果。

完整证据审计通过仅说明链路/归属可追溯，不认证 O/B 读图可靠。`v3` 与新版的 schema、选项枚举和解析条件不同，接口改善不能被混写为纯提示的视觉收益。
