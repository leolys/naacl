# 静态面板跨模型比较（xmodel_20260928）：R1 协议复刻 + R2 跨模型泛化

## 结论先行

本轮在 1×A100-80GB 上完成了两个模型 × 6 配置 × 140 任务（plain、v3、v4、v5、v6、v7）的完整重跑，共 1680 个配置单元、4414 次主请求，两个模型均 840/840 全部终态、无未完成单元。评分冻结使用 `evaluate.py` 的 `state()` 原文；所有接口失败与空选项保留在 140 分母内。

**R1（协议复刻，原模型 Qwen3.8-27B）**：v5"范围与条件实测"仍是六配置最高：90/140（64.3%），较普通方案 73/140（52.1%）净增 17 条、12.1 个百分点；McNemar 精确检验 p=0.0025，任务级 bootstrap 95% CI [+0.029, +0.214]。v4/v6/v7 分别 +13/+13/+16，全部 p<0.005 且 CI 不含零（v6 CI 下界恰为 0.000）。与 2026-09-27 原轮（v5 96、plain 81、净增 +15）相比，方向与量级复现，但**普通方案绝对值相差 8 条（81→73）**——同 seed 不保证确定性的直接事实证据，采样方差量级与配置间差异同阶，见 §4。

**R2（跨模型泛化，Qwen3-VL-8B-Instruct）**：plain 65/140（46.4%）；v4 +12、v5 +10、v6 +6、v7 +15，四个核验配置方向全部为正；v7 单独显著（p=0.043，CI95 [+0.007, +0.207]），v4/v5 为 0.05 之下的边缘不显著（p=0.158/0.089）。**防御收益跨模型迁移，但效应量缩小、部分配置单独不显著**——如实报告，不合并夸大。v3 在 8B 上塌方：51/140 接口失败（27B 仅 8），净 −15。

**新分析点（论文可用）**：v3 结构化协议的接口失败率与模型能力强交互（8B 51/140 vs 27B 8/140 vs 原轮 6/140）。在 27B 上 v3 的错误→正确迁移显著占优（30 vs 6，McNemar p=0.0001）但被接口失败完全抵消（净 +2）；在 8B 上则被彻底压垮。schema 严格度是独立于提示语义的实验变量。

**环境域负收益跨模型持续**：v5 相对 plain 的分领域净增，M1 环境 −5、M2 环境 −9；与原轮"环境域负收益"一致，如实保留（§6）。

本轮不支持的说法：未见数据泛化、真实网页提交恢复、解释链语义核实率、"8B 上 v4/v5 已被证明显著"。支持的精确说法见 §8 边界声明。

## 1. 跑了什么、没有跑什么

- 数据、图片、任务、选项顺序、原 gold、评分全部继承 2026-09-27 轮，逐字节校验（`tools/validate_handoff.py` passed：140 配对 / 280 实例 / 757 资产 / 3394 哈希）。模型输入不含离线标签、误导家族、历史评分或另一 arm。
- 六配置提示逐字复用既有 `prompts_{version}.py`，本轮未根据结果调提示。三段式（READ/VERIFY/DECIDE）与 plain 单请求结构同原。
- 新 runner（`xmodel_20260928`）：与原引擎同一纪律的独立实现——结构化输出兼容性探测、账本（ledger）逐尝试记账、**无质量重试**、已存在请求永不静默重放、非瞬态传输错误即停；断点续跑按 `result.json` 存在性。
- 先跑 M2（验证全链路），后跑 M1（复刻）。全部 1×A100-80GB 串行。
- 没有网页导航与提交（在线实验 P0-1 另行计划）、没有 held-out 家族切分实验（P1-3）、没有等预算普通重读对照（P1-4）、没有在线 API 模型。

## 2. 与原协议的差异（论文实验节如实声明）

| 维度 | 原 2026-09-27 轮 | 本轮 | 说明 |
|---|---|---|---|
| 硬件 | 4×H100-80GB，四副本并行 | 1×A100-80GB 串行 | 序列内串行性由调度保持 |
| 服务栈 | vLLM 0.19.1 / torch 2.10.0+cu128 | vLLM 0.30.0 / PyTorch（Lab 装版本） | `runtime_identity_xmodel.json` 留档 |
| 服务并发 | 每副本 max_num_seqs=1 | max_num_seqs=16，runner 并发 16 | 提速改动；解码参数不变 |
| HTTP 读超时 | 300 s | 900 s | 传输层参数；A100 尾部单请求实测可超 300 s（约 12 token/s） |
| 结构化输出 | 原 schema 形态 | 兼容性探测后取 `response_format` JSON schema 形态 | 探测与采用记录在账本 |
| 解码 | temp 0.7 / top_p 0.8 / top_k 20 / seed 12345 / enable_thinking=false（M1） | 逐字相同 | 同 seed 不保证确定性 |

## 4. plain 绝对值的采样方差：81→73 的教训

原轮 plain 81/140，本轮同模型同解码参数 plain 73/140。差 8 条（5.7 个百分点），且本轮 plain 的 bootstrap CI 半宽约 ±8 条。**同一配置两次运行的差异与多数配置间差异同阶**。论文表述必须因此调整为：配置间比较在同一轮内配对进行（本轮内部成立），跨轮绝对数比较需附采样方差声明。v5 结论的稳健性来自本轮内部配对检验（p=0.0025）加原轮同向结果，不来自跨轮数字对齐。

## 8. 边界声明（报告固定段落）

- 本轮是**单图原始标签相合**：已知数据集、固定候选、无浏览器提交。相合率不是语义正确率，也不是 O/B 释义核验正确率；env007 型"相合但理由跳步"不计入额外分数。
- 同 seed 不保证确定性；本轮与原轮的 plain 绝对差（81 vs 73）是实测采样方差，跨轮比较必须附此声明。
- v3 schema 与 v4–v7 接口不同；接口差异本身就是报告对象（尤其 v3×8B 的 51/140 接口失败），不能把全部差异归因于提示语义。
- 不做逐题择优拼接；不事后改 gold；不新增版本；本轮结果不回写旧 manifest。
- M2 的 v4/v5/v6 未达 0.05 单独显著：如实报告为"方向一致但单配置检验功效不足"，合并证据的说法仅限于"v4/v5/v6/v7 方向全正"。
- 提示迭代史集中在 dev24；其余 116 不是历史完全未见任务。
