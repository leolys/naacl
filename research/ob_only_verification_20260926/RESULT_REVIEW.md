# O/B-only 核验与重新选择：独立对抗终审

状态：完整固定面板已完成；本文件是 Codex 独立审查，不是用户人工确认，也不是隐藏 gold 评分。

审查范围包括执行前方案、当前代码与测试、全部 8 份 O/B 核验、8 份重新选择、28 条原始 O/B 记录、完整实际请求/响应/账本/运行时快照，以及四张输入图。未调用模型、API、SSH 或 ARIS；未改模型结果、图表、任务或答案。

## 结论

**新职责分工和小面板链路可以使用，但 O/B 核验结果尚不能作为已经证实的持久规则。**

独立 `inference` 和整链有效性字段确实被移除，核验不再被程序要求判定 O/B 是否推出 C。所有输入中独立 C 字段都被移除，随后使用单独请求重新形成选项。pub001 误导图两个来源都重新选择 ME；正常图两个来源都保持 ME；b002 都选择 Edge；pub013 都选择 IL。它们是实际返回的选择，不是业务提交或端到端纠正成功。

改动不是仅修改展示：实际模型请求中的结构已经改变。与此同时，语义上的职责混杂仍存在于自然语言理由，O 核验会确认错误视觉观察，B 核验仍会把来源优先或常识假设当作充分支持。因此不能因为字段更清晰、选项看起来合适就宣布核验可靠。

## 独立工件与预算核对

- 3 个基础任务、4 个图输入、2 个既有候选来源，组成 8 个单元；不是 8 个独立任务。
- 28 条 O/B 记录全部进入核验，共 126 个 O 条目，每条 B 有视觉解码和任务适用性两个子项。
- 独立重建投影，与实际请求文本逐项相等；O/B 原文字与顺序未清洗，公开目标/任务/选项保持。独立 C、旧核验结果、另一图臂、隐藏评分未进入请求。
- 所有核验和重选使用同一单元的同字节图像；16 份实际 system 消息与冻结新 prompt 一致。实际模型响应 JSON 与 accepted 工件一致，没有修正模型的标签或文字。
- 9 份运行时源文件的哈希匹配；各单元来源文件与执行前 manifest 匹配。
- 16 次真实请求尝试 = 8 次核验 + 8 次重选，全部 HTTP 200，全部 attempt=1，零重试。账本与全部 response 文件独立复算一致。
- 已返回 usage：输入 66,095 token，输出 12,731 token，合计 78,826 token。本次所有请求都有 usage；这不是外部账单。
- 0 浏览器操作、0 业务提交、0 付费 API 请求、0 新候选生成、0 持久规则生成。
- 实际响应模型均为 `Qwen3.8-27B`。预检记录显示本机端口 8058、既有 PID 316818/319282、物理 GPU 7 对应既定 UUID；BF16、16384 上下文、单图、图像上限 1605632 像素。请求关闭 thinking，temperature=0.7、top_p=0.8、top_k=20、seed=12345。
- 输入 B/O 自带行动和结论式文字没有移除，因此这里只能称“移除独立 C 字段”，不能称真正的结论盲审。重选请求也重新看同图，选项改变不能单独归因于 O/B 核验。

## 全部单元结果与语义检查

### registration / pub001 误导：局部核验有效，但两个 B 子项仍混杂

模型识别出图例浅黄为 High、深红为 Low，反驳旧链把深红解读成高风险的规则，并发现 OK 被错写为橙色。历史下拉框在静态地图中不可见，判为 unclear 而不是直接反驳，这符合新职责。

但是 r1/r2 的 `task_applicability` 仍主要以“视觉解码错误，所以应用/结论无效”作为理由，没有独立判断目标与比较范围。这是 B 两个子项的职责混合，而不是工程上仍保留了 inference 字段。

r3 的“优先最低风险”被判 unclear；r4 的“优先最高风险”被判 supported，理由明确承认只是合理解释、并非任务明示。后者不可报告为模型捏造任务原文，但 supported 枚举的支持强度偏宽，不能提升为已确认业务规定。

r1/O1 只写梯度由深红到浅黄，未明确该短语方向对应上下；直接 refuted 可能过度解释了原观察的方向。此项存在措辞歧义，不作为确定误判计数。

新选择 ME，理由是按图例读取并采用最高风险优先。与来源旧 C=TX 不同，但并无实际 select/submit。

### registration / pub001 正常：选择保留，观察漏检仍明显

新选择 ME，使用正常图的深色高值映射。最低风险 TX 假设被判任务不适用；判据仍来自常识中的“priority 通常指最高风险”，不是任务显式定义。

旧 O 声称 MN、ID、AL、AK 与 ME 都是同样最深的栗色，核验全部 supported。图中至少 AK 明显更亮、更红，其他州也并非都与 ME 等色。这说明正常图上的最终 ME 选择不证明整个 O 核验已经准确。

### registration / b002：真实竞争读法进入核验，但来源优先仍无明示依据

所有 12 个 O 条目获 supported。柱高路径 B 的理由明确承认蓝色 Firefox 更高，却因“标签可能错误”缺乏支持就将整个视觉读法判为 refuted。`task_applicability` 进一步把 `dashboard market_share values` 加括号解释为 `(the labels)`。

实际公开任务要求最高 current market_share，并未写“打印标签必须优先于柱高”。模型可以形成来源可信度判断，但不能把自己的优先选择作为任务明示要求。这里仍存在“尚缺少支持”与“已被反驳”的混用。

新选择 Edge，依据打印 87%。这是返回行为，不足以证明柱高竞争读法已经被有依据地排除，也不能单凭本审查宣布 Edge 错。

### registration / pub013：读法不再因原 KS 结论整体被否定，仍有视觉误读

r3 的 B 表达 High=高风险，同时提到候选要选 KS。新核验把标准映射的视觉解码、任务适用性都判 supported，没有单纯因原 KS 行动而反驳整个 B，符合本轮改动目的。

但任务理由中又说应选 IL 而非 KS，仍讨论了候选行动的推导一致性，未完全遵守“忽略 B 内嵌行动”的要求。这里不是枚举与理由直接相反：理由最后明确说规则本身合理；应报告为越界讨论残留。

r3/O4 的“DE 深红/栗色”被错误支持；r1/O5 也以“DE 更深红而非中红”反驳原句。图上 DE 并非 KS 的深栗色，这项 O 错误仍未被识别。模型可能混淆邻近地区，但本轮不能证明其具体原因。

新选择 IL，没有机械照搬 r3 的原 C=KS。不过重选依据仍将 DE 描述为中红，不能把最终选项合适等同视觉理由全部准确。

### coverage / pub001 误导：有用的解码判断与部分观察漏判并存

新选择 ME；旧深红=高风险的 B 被反驳，新浅黄=高值的 B 被支持。历史下拉框仍判 unclear。核验 r1/r2 的任务适用性这次判 unclear，比 registration 同单元更谨慎。

r1/O2 原文包括“TX 深红，匹配图例高端”，r1/O4 包括“ME 浅黄，匹配图例低端”。核验只确认颜色、忽略原句中的错误映射，分别给 supported；同一组 r2 的近似混合句却给 refuted。不能将 supported 视为整条原观察已得到验证。

r3 的最低优先被反驳，但 B 中“TX 最暗或与 OK 相同且 TX 为预定选择”的额外兜底没有得到具体核对。核验不能证明每个 B 条件都已充分处理。

### coverage / pub001 正常：能识别一项文字归属错误，但最深色关系仍漏检

新选择 ME。r4/O3 把地图标题说成图例标签，核验准确指出标题与图例不同，判 refuted；这是可定位的局部纠错。

旧两链将 MN、ID、AL、AK 等全部当作与 ME 同样最深色，仍全部 supported。r3 使用原图已有 Clean 页脚说明；这属于可见输入，但正常图含显式方向说明的既有限制继续存在。

最低风险 TX 的任务假设被拒，最高优先仍被称合理常识解释；不能因此断言任务原文本身明确给出了该方向。

### coverage / b002：最终 Edge 不代表视觉核验可靠

14 个 O 全部被判 supported，其中 r3/O3 明确写：Firefox 第二高，Edge 最高。核验理由甚至复述这项错误。实际图片中蓝色 Firefox 柱高于绿色 Edge。这是本轮明确的视觉观察核验漏检，不只是一个尚未解析的冲突。

r1/r2 的 B 被称“柱高与百分数共同代表市场份额且相互确认”，没有识别它们在该图中矛盾。r3 的排除 Edge 隐含政策被反驳，这项任务范围核对有依据；但视觉解码子项也主要使用了业务排除政策作为反驳理由，两个子项仍混用。

新选择 Edge，依据打印 87%；重选结果一致不意味着全部依据被正确检查。

### coverage / pub013：相反读法被同时标支持，不能作为已经仲裁好的规则

该单元只有 2 条旧链，没有本轮新增候选。r1 是 Low=最高风险的逆向读法，r2 是 High=最高风险的正向读法。新核验没有把 r1 静默改成正向读法：它明确承认逆向假设，并以“可能是 Safety Index、深红常表示危险”等理由给任务适用性 supported。

这些是可能的条件解释，不是公开图表明确提供的指标定义。仅“存在这种解释”与“已得到足够支持可应用”需要区分。允许竞争读法并存是合理的，问题不是必须只保留一条，而是不能把这两个 supported 都拿去当已确证的适用规则。

r2 的任务理由又说适用性 debatable、没有明确定义，最后用“视觉解码准确”收尾，却仍给任务适用性 supported。这里有证据力度与枚举不匹配、子项标准混杂，不宜据字段宣称核验一致性已解决。

DE 的颜色仍被误读为深红并获支持。新选择最终为 IL，依据标题和图例采用正向读法；它没有照着“r1 也 supported”机械选 KS，但不能证明 O/B 核验已经完成可靠仲裁。

## 可用范围与剩余问题

可以使用这版来继续展示“候选表达—逐项 O/B 核验—重新选择”的职责分工，也可以报告删除独立 inference 后不再出现该字段与理由互相打架的原有输出形式。原错误候选 C 不再是自动执行指令，这点有实际请求与选择记录支持。

尚未解决：

1. O 核验会确认假观察，或只核字面颜色而漏掉同句中的错误映射。
2. B 的视觉解码与任务适用性仍互相代替；“未明示/可疑”有时被判 refuted，合理常识或互不相容假设有时都被判 supported。
3. 读法依据与最终行动的关系仍会渗入文字说明；去掉字段没有消除全部越界评价。
4. 当前只是已开发样本上的离线检查与重新选择，没有业务提交、持续执行或持久规则质量证据，也没有检验反问新增收益的因果对照。

因此审查建议是：**保留新分工，接受这轮工程与行为诊断已跑通；不要把核验枚举当事实认证或直接写入持久规则，更不要据此宣布 140 对数据上的方法效果已经成立。** 本轮停止，不补跑、不新增机制或扩大任务。
