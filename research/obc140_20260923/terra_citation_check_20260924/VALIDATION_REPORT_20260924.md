# Terra 通用引用兼容验证结果

**引用兼容修正已验证生效；两个新鲜开发例的四阶段流程均完成。但核验内容不是全部正确：b001 的几何竞争链出现了一次证据不足的观察否定。140 条批量没有启动。**

## 本次修了什么

旧核验提示允许引用公开任务，但旧结构校验把所有 evidence 都当作图像引用，拒绝了 Terra 的 `task_001 / user_goal`。

新增适配器只做来源分离：实际存在的公开任务字段引用移到 `task_evidence`，同时保留模型原话、请求中真实字段原文及“仅定位来源，内容未验证”的状态。图像引用继续单列，每条核验仍必须有图像证据。任务文字不能搬进 O，未知来源、其他任务、不存在字段、无图像证据的输出仍拒绝。

没有更改原图、任务、gold、生成／核验提示、判定标签或推荐选项；没有修改旧 engine、panel_core、run_panel。来源绑定不证明模型的转述、观察判断或结论为真。

## 三类证据分开记录

### 1. 旧响应离线重放：0 次模型调用

四份旧核验同时经过原校验与新适配校验：

| 旧记录 | 原校验 | 新适配校验 | 行为 |
| --- | --- | --- | --- |
| Sol / b001 | 接受 | 接受 | 内容不变 |
| Sol / pub013 | 接受 | 接受 | 内容不变 |
| Terra / b001 | 拒绝 | 接受 | 一条任务引用被分开，原内容与判断保留 |
| Terra / pub013 | 接受 | 接受 | 内容不变 |

这是确定性兼容重放，不是四条新的模型成功。旧 Terra/b001 的 invalid 记录仍原样保留。[完整重放](offline_replay.json)

### 2. 新鲜真实运行：2 个已知任务，共 8 次请求

模型为 APIYI 请求及回报的 `gpt-5.6-terra`。每例独立重新生成提案、解释链、核验和中文；并发 1、无重试、无浏览器业务动作、无 GPU。输出上限保持 700 / 2200 / 2200 / 6500，temperature=0，未额外设置内部推理预算。

| 任务 | 四阶段结果 | 生成链 | 任务引用迁移 | 同一新响应交给旧校验 |
| --- | --- | ---: | ---: | --- |
| b001 饼图 | 全部完成 | 2 | 2 | 仍会因任务引用而拒绝 |
| pub013 风险地图 | 全部完成 | 1 | 0 | 原校验也接受 |

b001 直接证明本次新模型响应触发了适配分支，不只是旧响应重放。pub013 是普通图像引用的回归检查，不算第二次迁移分支验证。

所有 8 次均 HTTP 200，完整用量回执可用。两份新提案请求与旧 Terra 提案请求整个消息体相同；随后阶段的系统提示、图片和解码设置保持不变，但各自新生成的提案／链不同，因此后续消息体并不相同。中文阶段还会收到新增的来源字段。不能把重新生成出的差异归因于引用适配提高了视觉能力。

### 3. 内容审查：兼容通过不等于语义全通过

**b001 的主链基本合理。** O 记录 Apple 45%、Xiaomi 30%、Samsung 15%、Others 10% 等原图文字；B 说明按公开任务采用打印值；C 才比较大小并选择 Apple。本次也产生了以扇区角度为依据的竞争链，而不是只换答案。

**需要保留的核验问题：** 几何竞争链称红色 Others 扇区略大于其余扇区；图面上它与浅黄 Samsung 接近。核验用“Samsung 与它接近”推出“并不更小”，从而把该 O 判为反驳。接近并不能反驳略大；若辨认不清，也不应直接判定观察为假。这是原模型输出中的过度否定，适配器未改写它。

公开任务不允许按误导的扇区大小决定预算，因此否定几何规则在本任务中的适用性、拒绝 Others 行动有依据；这并不能反过来证明几何观察为假。最终 Apple 选择得到支持，也不能掩盖副链 O 的问题。

**pub013 的分层基本合理。** O 为 IL 浅黄、DE 更深、KS 深红，以及图例的 High/100 和 Low/0 字样；B 才解释颜色与风险，C 才得到给定三个州中的 Illinois。没有将“高风险”偷渡到 O，也没有把图例端点当作州的精确数值。仍只生成一条主链，没有展示竞争解释覆盖。

中文保留条件、数字和原英文判断，也忠实保留了上述有问题的几何反驳；未由 Codex 补译或纠正。部分图中标题／英文州名未附完整中文释义，阅读层仍有这一小限制。翻译结构检查无告警不等于语义已被自动保证。

以上是 Codex 离线复核，不冒充所有者人工标签。[逐项语义复核](POSTRUN_SEMANTIC_REVIEW.md)

## 费用与全量参考

按此前查证的 APIYI 公开 Terra 输入 $2、输出 $12、缓存读取 $0.2／百万 token 计算；缓存写入收费仍不明确。请求回执只有 token 用量，没有账户实扣。[既有公开价格来源](https://docs.apiyi.com/models/gpt-5-6-terra)

本轮输入 79,418、输出 9,241 token。其中提示缓存读取 22,830、写入 56,564；读取命中出现在两个提案调用中，不把它说成经独立确认的纯图像缓存。重复的用量别名没有叠加，推理 token 没有在输出总数之外再次计费。

| 估算情景 | 本轮两例 | 两例均值 × 140 |
| --- | ---: | ---: |
| 按实际回执缓存读取量，不额外收写入溢价 | $0.228634 | $16.00438 |
| 在上一项上，仅对回执写入量加 25% 输入价 | $0.256916 | $17.98412 |
| 假设未来不能复现本轮缓存读取折扣，读缓存量改按普通输入 | $0.269728 | $18.88096 |
| 在上一项上，原读缓存量也按新写入处理，加未确认的 25% 写入溢价 | $0.309425 | $21.65975 |

对尚未使用的任务做预算时，**不应直接沿用本轮缓存优惠；可参考后两种假设下约 $18.9 / $21.7。** 这些不是已确认上下界、置信区间或报价；两个已知开发样本不代表 140 条的长度与失败分布，也没有计入未来重试。相比上一轮 Sol 的约 $33.7 / $39.2 外推，Terra 有降本空间，但不是等输出、等质量的严格成本比较。

费用汇总另经子 Agent 按原始回执独立复算，8 次预算事件逐项对齐。[逐请求用量、输入对比和敏感性计算](cost_and_comparability.json)

- 引用适配与固定范围单元测试 90 项通过；包含原有管线的联合回归共 118 项通过，三条既有依赖弃用警告，无失败。
- 对抗代码审查在首例启动前通过，随后完成审查工件；第二例在首例流程完成及内容检查后才启动。首例的语义问题被保留，不作为调整提示或多跑的理由。[代码审查](PREDEPLOY_REVIEW.md)
- 本轮七个复用源文件的运行快照与旧 Terra 源快照一致。新增适配和新入口另存；旧结果不追写新版本身份。
- 新阅览页已实际用 Edge 检查，两张原图内嵌、无外网请求；仅为阅读界面验收，不是业务任务执行。

新增代码为 `citation_adapter.py`、`run_validation.py` 及离线汇总／展示工具。完整请求、响应、原始与适配后核验、配置和代码快照位于 `run/`。复核命令与全部工件见 [工件索引](MANIFEST.md)。experiment-bridge 的独立审查和单例先行约束已执行；render-html 仅生成报告阅读视图，不改变模型结果。

## 本轮决定

**可以把该适配作为 Terra 后续静态生成配置的基础，但当前只能把生成与核验记录当作待人工审阅材料，不能当作可信金标。** 接口故障已解决；语义核验仍可能出错。两例提案原本就选中有支持的选项，没有测试纠错收益，也没有证明防御对 140 对 benchmark 有效。

本轮停止：不改提示继续追逐更好答案，不启动 140 条，不开发新机制。是否采用 Terra 做全量、以及批量费用上限，仍待用户确定。
