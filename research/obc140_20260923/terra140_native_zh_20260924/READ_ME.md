# 如何阅览这 140 条解释材料

## 给阅览者

双击 `OBC140_TERRA_ZH_REVIEW.html` 即可离线打开；把这一个文件复制到其他电脑也可以展示。图像、文字、样式均在文件内，不需要项目环境、API 密钥或服务器。

1. 在左侧搜索任务编号，或按领域、生成状态筛选。
2. 先读公开任务和选项，再点击图表放大查看原图。
3. 查看模型的初始提案，再看 O（观察事实）、B（解释规则）、C（推导结论）。中文、英文和中英对照均可切换。
4. 对照不同解释是否真正导向不同选项；多个解释指向同一选项时，不算行动之间的竞争。
5. 查看逐链核验和规则状态；展开原始记录，可以追溯模型返回了什么、哪些内容未通过接口校验。
6. 在“我的审阅笔记”中记录意见并导出。笔记默认只在当前浏览器保存，复制 HTML 不会自动携带笔记；换电脑时请同时导出／导入笔记文件。

`PREVIEW_IN_PROGRESS.html` 是过程快照，不是最终交付，也不会随运行自动更新。最终完成情况以 `REPORT.md` 和最终 HTML 中的状态为准。

初次阅读可搜索以下编号，了解几种不同状态；它们来自固定开发审查，不能代表总体准确率：

| 编号 | 建议重点看什么 |
|---|---|
| b002 | 正常完成的解释、核验与中文对照 |
| b010 | 有生成解释，但核验达到长度上限；原始截断片段如何保留 |
| health010 | 多条解释指向同一选项；规则 active 但行动蕴含被反驳、推荐为空 |
| pub001 | 图表局部排序与后续网页操作完成证据的区别；单链不冒充竞争链 |

## 三个容易混淆的区别

| 页面内容 | 实际含义 | 不能据此声称 |
|---|---|---|
| O／B／C 解释链 | 模型显式输出的短论证记录 | 模型内部思维过程，或人工确认的事实 |
| 核验完成／规则生效 | 核验输出通过当前接口校验，程序按其判断记录状态 | 判断一定正确，或网页动作已执行 |
| 推荐改变选项 | 核验推荐与初始提案不同 | 已纠错成功，或最终任务提交正确 |

这是静态图表解释材料，不是多步网页操作实验。页面没有模拟点击或伪造最终提交。本轮不根据隐藏答案给模型的改变判“正确”，也不把核验器自己的判断作为 gold。

尤其注意：某条规则的 `active` 状态不代表整条 O → B → C 链成立。必须同时查看观察判断、规则判断、行动蕴含判断（`implication`）和最终推荐（`recommendation`）；例如规则可保留，而行动蕴含被反驳、推荐为空。

## 失败与中文翻译

原模型英文记录保持不变。中文是独立阅览层，由 Codex 翻译；不额外调用 APIYI，不替模型补全截断回答，不纠正其判断或数值。数值／键检查属于工程核对，不能证明全部译文或解释都正确。

执行协议沿用了纯格式处理：仅生成阶段、正常停止的回答允许补末尾 JSON 闭合符；规范化时最多按原输出顺序保留三条候选。原始响应、原始解释及处理记录均保留。它们不是人工语义修复，也不用于补全达到长度上限的截断回答。

未通过结构校验但已返回的解释会标为“原始草稿”；回答截断时保留真实片段。没有实际执行的核验不显示为核验成功。审阅提示来自单独的 Codex 开发审查，不替代数据所有者的人工审核。

## 给需要追溯的研究者

- `config.json`、`PLAN.md`：本轮范围、提示版本、调用限制和复用规则。
- `run/tasks/<编号>/record.json`：规范英文记录；其中 translation 始终为 not_run，因为本轮原生翻译另存，不是漏译。
- `run/tasks/<编号>/<阶段>/round_001/request.json`：完整真实请求，包括公开输入及图像。
- 同目录的响应、attempt 文件：原始返回、用量、耗时、错误与重试记录；文件名以实际工件为准。
- `run/runtime.json`、`run/runtime_source/`：运行时配置／源码身份，不拿后来展示代码冒充当时模型协议。
- `translations/inbox/`、`translations/outbox/`：去重英文及其中文映射；`review_data_zh.json` 将译文映射回任务字段。
- `failure_audit.json`：离线复查接口失败原因，不调用模型，也不修复旧答案。
- `SEMANTIC_REVIEW.md`：固定小面板的审查覆盖范围和发现；未审查任务不等于无问题。
- `cost_summary.json`：真实请求用量和估算口径，不是账户账单。
- `delivery_checks.json`、`browser_check.json`、`offline_tests.xml`：工件一致性和展示／代码测试，不是研究假设验证。

两条英文记录 b001、pub013 复用此前兼容性检查，均明确保留来源；不计作本轮新请求或新的独立任务证据。140 条对应原有 140 个任务的误导图条件，不是 280 个成对条件。

工件包保留历史路径用于溯源；只有单文件 HTML 承诺可脱离项目离线展示，代码运行仍需要配置本机路径和经授权的服务。API 凭据由运行时环境提供，不主动包含在交付中。打包前扫描全部候选文件中的已知密钥形式；这不是对所有秘密类型的绝对安全认证。
