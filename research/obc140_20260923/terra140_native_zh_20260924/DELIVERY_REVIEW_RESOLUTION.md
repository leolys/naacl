# 交付复核问题的最小修正

原始意见保留在 `DELIVERY_CODE_REVIEW.md`；本文件是执行者的修正说明，不冒充第二轮独立审查。

1. 最终检查只接受完整队列的终态，要求 140 条规范记录按提案／生成／核验三个 API 阶段真正结束、翻译输入准备完成。主执行者复查时另外发现共享 `core.PHASES` 还包含旧 API 翻译阶段，因此改为明确使用三个阶段，并增加回归测试。原生中文仍单独检查，不伪造 API 翻译完成。
2. 浏览器验收记录最终 HTML 与阅览数据的哈希；阅览数据逐条绑定当前规范记录哈希。打包前必须有工程检查与浏览器检查 PASS，文件和全部 140 条记录仍须匹配，不能凭一个陈旧 HTML 存在就归档。
3. 打包扫描扩展到所有候选文件的原始字节和带 BOM 的 UTF-16 文本，不再漏扫 XML 等后缀。声明限定为已执行的密钥模式扫描，不声称能识别所有秘密类型。

新增四项小型离线测试覆盖运行中队列、陈旧 HTML、字节／UTF-16 扫描，以及 API 三阶段和独立中文侧车的区别。本轮最新回归结果为 **56 passed**，另有 3 条原有 Flask／itsdangerous 弃用警告，见 `offline_tests.xml`。

没有修改冻结的模型客户端、提示、原图、任务、API 运行结果或调用预算。最终全量检查及浏览器结果分别以 `delivery_checks.json` 和 `browser_check.json` 为准；单元测试通过不证明模型解释正确。
