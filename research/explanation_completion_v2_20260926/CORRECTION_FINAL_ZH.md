# O–B–C 协议修正：具体结论与核验职责分开

> ⚠️ 本页是 2026-09-26 的协议与代码修正说明，不是新模型实验结果。被测 API 请求 0 次，GPU 0，业务操作 0。旧三例输出与旧展示保持原样；新版真实核验均为“未运行”。

## 修正的核心

保留每条解释链具体的 C，不强制改为同一个命题的“是／否”。先表达“按照这条链明确采用的 O 和 B，会得到什么结论”，再分别核对观察与规则在当前图上的依据。存在另一条竞争解释，不会自动把本链的条件性结论抹成“不确定”。

同样不能强求结论：若确实缺少必要比较、实体对应、解释条件或任务条件，应记录具体缺口。不能推出某命题，不等于可以推出它的否定。反问仍负责补齐解释集合，不是强求新链、冲突或纠错。

## 原协议与新协议的区别

| 对象 | 上一版的实际问题 | 新版处理 |
|---|---|---|
| C 的表达 | 虽保留条件性自然语言 C，但后续 implication 混入条件是否得到证实 | 原 C 保持原文；具体说明该解释下支持或反驳什么，不统一二值化 |
| 条件推导 | “假设成立则推出”与“假设当前可信”混用 | conditional_inference 只检查按明示前提能否推出该 C |
| 规则的图上适用性 | B 可能只因条件规则合理就被标为 supported | B_applicability 必须检查当前图和公开任务是否支持这些条件 |
| 竞争解释 | 冲突可能只留下支持不足说明 | 缺少且有可见动机的不同读法可以形成具体新链；已有两链不强求第三链 |
| 规则状态 | active 容易被误读为整链或答案确认 | 只聚合 B_applicability；条件推导 valid 不能把待核验规则激活 |
| 细化记录 | 与完整 O–B–C 共用核验槽位 | 单独核验细化自身的支持情况，不给没有独立 C 的说明强造推导 |

## 三个核验字段分别问什么

| 字段 | 问题 | 允许状态 |
|---|---|---|
| O | 文字、标记及实体对应是否确实可见？ | supported＝有支持；refuted＝被反驳；undetermined＝依据尚不足 |
| B_applicability | 当前图是否支持该解释规则，适用条件是否满足？ | supported、refuted、undetermined |
| conditional_inference | 接受该链明确列出的观察和解释假设后，能否推出该具体 C？ | valid＝条件推导成立；invalid＝存在推导错误；incomplete＝缺少明确前提 |

valid 不表示前提已被图证实，更不表示动作可以提交。invalid 不表示 C 的反命题为真。incomplete 必须列出尚未陈述的必要前提；“已有假设的真假未证实”应放在 B_applicability，而不是伪装成缺失前提。

推导引用当前链和它实际依赖的规则。这里的引用用于定位假设，不充当图像证据。观察与规则适用性的支持／反驳仍必须引用当前图或准确的公开任务字段。代码只检查结构及引用，不充当自然语言逻辑证明器。

## b001 应如何表达：口径说明，不是新版运行结果

旧原链写的是：在打印百分比代表当前份额的解释下，Apple 的 45% 最大，因此选择 Apple。旧核验却因面积和文字不一致、未说明采用哪种编码而把 implication 标为未确定。

新版要求将两件事分开：

1. **该条件下的结论**：保留“按打印数值解释，选择 Apple”，不因另有面积解释而改成无结论。
2. **该条件当前是否适用**：由 B_applicability 对图和公开任务核对，不能仅因“如果……那么……”在逻辑上合理就当作已证实。

如果反问发现缺少有依据的面积读法，可以补充“Others 扇区比 Apple 大；若面积表示份额，则 Apple 不是最大对象，因此不应选 Apple”。这是用于说明新版表达方式的候选示例，不是本轮 API 生成记录，也不证明应该选择 Others 为全图最大对象。

如果初始集合已经完整表达这些读法，反问可以不新增。不可把这个示例作为只针对 b001 的固定答案或必生成规则写进提示。

## 当前动作命题来自哪里

用户原稿以公开任务和真实动作提议构成当前判断，而不是独立编造一个“固定命题”。新版可读取旧真实 actor 提议的公开选项，形成 decision_reference，供生成／补齐知道正在讨论哪项选择。

该参考不取隐藏答案、不挑初始链、不带入旧 actor 理由或旧核验结论。它不是已执行的 current selection。独立核验器仍只接收图、公开任务与全部候选，不接收原提议偏好字段。

每条新链可以显式记录其与提议的关系：支持、反驳、其他候选或未涉及；系统不因选项不同就自动判为反驳。旧链没有该字段时不会事后补造。具体 C 始终保留，因此不丢失替代选择、比较范围或仅否定一个对象的信息。

## 文件与使用范围

- prompts.py：共享生成、反问、补齐、核验提示；不含样本编号或品牌答案规则。
- core.py：新版核验与状态接口；复用旧完整集合与补齐逻辑。
- workflow.py：原三例输入准备、公开上下文投影、离线模拟编排；没有付费客户端或 live 入口。
- prepared_final：原三例完整请求预览及未核验状态，不是执行结果。
- mock_route_demo_final：明确标记为虚构测试的各阶段输入、输出和规则重载记录。
- tests：结构、引用、状态及新旧隔离回归；通过不代表语义正确。

本目录是当前“三例解释集合补齐协议”的新版本，不自动替换其他并行实验或在线防御 runner。旧 explanation_completion_20260925 及其展示仍代表当时真实输出。

## 停止点与剩余限制

本轮完成离线修正后停止。新提示能否让真实模型更好地表达竞争解释，需要新授权的有界验证；本轮不继承已结束面板的调用预算。

这次没有开发观察选择器、回滚或大型多 Agent 系统，没有扩大样本，也没有宣称防御效果提高。即便条件推导检查写成明确枚举，模型仍可能错误判断逻辑或规则适用性，需要保留原始依据供人工审阅。
