# 调整后的方法：同次执行内的解释集合补齐与规则状态维护

本文件是对原方法稿的本轮实现说明，不覆盖原稿。主设置不要求先完成一次任务再重跑，也不要求单次模型调用直接答对。规则的持久范围是一次任务；任务之间不共享答案、图表解释或评分反馈。

## 1. 基础对象与介入时机

Agent 根据用户任务 q、实际观察 o_t、真实历史 H_t 和已有任务内规则状态，提出尚未执行的动作。首次提出非空图表选项时，执行器暂不点击。所有选项与两种图表条件使用相同入口，不以隐藏答案或错误检测为触发条件。对于原环境，首页/图表页/表单导航仍由普通 Agent 执行，不把导航称为一次已完成任务。

解释链记作 O ∧ B ⇒ C_q(a)：O 记录局部图形与打印文字，不提前放入风险排序、趋势解码、数值计算等结论；B 记录映射及适用条件；C 记录条件性任务判断。打印文字与常见几何惯例均不自动具备优先级。

## 2. 初始集合与反问补齐

初始生成可一次产生多条链，完整保留其顺序、共享规则和证据绑定。反问检查这个集合的观察、解释条件与覆盖缺口，不负责必须发现冲突或证明错误。输出可以是新增解释、细化已有解释、指出已有覆盖、仍未解决。允许零问题、零新增、不同依据支持相同选择；重复措辞不增加证据权重。

本轮生成最多 3 条初始链，反问最多 3 个问题，补齐最多 2 条新链与 2 条独立细化。已有规则 ID 不重排；新链使用独立 ID。细化记录不悄悄覆盖原链或激活修改后的原规则。

## 3. 独立核验与规则状态

完整候选集合交给核验调用，逐项检查 O、B、推导，状态为支持、反驳、未确定。核验不接收反问者的覆盖结论作为证据，也不按来源身份或重复次数投票。图像引用与公开任务文字引用分开；后者绑定精确字段及原文。

状态保存：任务/具体图像范围、编码组件、条件、稳定规则 ID、版本、B 状态、各链的三维核验、依据和修订历史。只聚合 B 判断得到 active/revoked/pending/disputed；观察错误不会自动撤销规则。B active 不能单独授权动作。输出状态保存并重新读取后，才进入下一次 actor 输入。

## 4. 重新推导、执行与后续读取

核验不直接选择或提交。Actor 收到同一公开环境、完整真实历史、已核验解释集合和带状态的规则，再提出实际操作。图表选项/提交须明确引用受到三维支持的链、当前规则版本和适用条件判断。代码只校验这些声明与记录一致，不充当看过 gold 的视觉裁判；模型的条件判断及核验仍可能错误。

保持当前选项是合法结果。所需选项已经选中且必填项完成时，允许正常提交，不强制改选。若有新图内/公开任务证据挑战先前核验，可在固定预算内复核；规则版本更新并保留旧状态与依据。若证据不足或复核预算耗尽，明确未解决，不强制提交。

记录分离：核验三维判断 → actor 重推导推荐 → 执行器实际选项 → actor 最终提交及原服务器收据。收到状态、声称引用规则、真正产生后续动作是不同观察；本轮不以状态文件存在或选项未变化证明持久化因果收益。

## 5. 本轮实现的覆盖与未覆盖

接入四类原网页应用，保留原图、页面、原始选项顺序、正常 POST 与原评分。单元测试中的程序化 actor 和真实模型结果分开。任务之间清空规则及浏览器状态；旧解释、旧结果、另一图表条件和隐藏评分不进入被测模型。

本轮固定开发任务主要是单个图表选择加提交，只检验在线生命周期和规则交付链路。尚不能证明复杂后续语义决策中的持久性收益，也没有通过本轮证明反问优于等预算普通重读。后续独立实验应使用原任务中实际存在的后续图表判断；不为凑证据增加无意义的重复选择或循环。

工程调试修复可直接复现的通用接口错误，不以答对或新增竞争链为停止条件。大规模运行前还需要完整资产可用、配置与预算明确、失败分类和可追踪断点；本轮不自动开展全量实验。
