研究协议沿用 [已预先写定的协议](../preparation_20260907_v1/PILOT_PROTOCOL.md) 与 [原任务清单](../preparation_20260907_v1/TASK_MANIFEST.json)，不改任务、图、gold、顺序或三策略的公开提示。此文件补充可执行调度与控制，不建立新视觉方法。

## 模型候选与权限

用户授权在指定网关查询模型并选择 GPT 系列。已观察到 `gpt-5.6-sol`；选择它作为强模型候选。[官方页面](https://developers.openai.com/api/docs/models/gpt-5.6-sol) 将其列为旗舰模型，支持图像输入及 Chat Completions；官方默认 reasoning effort 为 medium。拟用 `medium`、`max_completion_tokens=8192`、图像 `detail=high`，不附加 temperature。先在下面的非图表控制验证正常输出，不能用 8 个任务校准。

该名称可见不证明网关实际路由。后端逐请求分别保留 requested model、response model、`usage.model_name`。当前预期后两者均为 `gpt-5.6-sol`；缺失、不同或自动路由至其他模型就停止整个面板，不静默放宽接受名单。即使二者相符，也只算网关报告的身份，不是独立权重证明。

本轮金额、共享 GPU0 / 本地服务、新面板 400+400 次调用 / 4000 transition 权限仍待确认。查询授权不是不限额生成授权。密钥不入文件，生成后端只读 `MODEL_API_KEY`。

## 启动控制

两后端先完成初始化；强 API 控制先于本地控制，两者全部结束之前，不生成任何正式任务前缀。一次固定的控制计划，不失败后反复改提示：

- 每模型四个非图表流程：公开目标 Route A/B × 当前选项 A/B；每场景最多两次普通 actor 调用，真正提议提交才执行。公开目标确定控制的预期行为，不读取 benchmark gold。
- 每模型两次图像顺序控制：红图、蓝图，交换顺序再问一次。调用使用相同后端和解码参数，不给出当前图的答案；验证服务是否实际处理了两个输入。
- 每模型最多 10 次调用，计入该模型的 16 次控制额度与 400 次总额。剩余控制额度不是反复调参直至通过的许可。
- HTTP、路由、截断或控制失败时保留全部 96 个未运行记录，不启动 Qwen-only 替代面板。

## 正式调度

严格读取原 32 个 case-interleaved 单元与各自策略顺序。两个模型各自从初始页自然执行；每条前缀最多 12 次调用、20 次实际 transition。未到 hook 则三配置记录为未执行核查，继续预定的下一单元；全局/单模型总预算耗尽则整个面板停止。前缀局部额度和总额度耗尽有不同终止原因。

首次真实 submit proposal 暂存。每个分支新建页面，用真实前缀动作重放，逐字比较公开状态、逐像素比较截图。匹配才执行该分支；不匹配记恢复环境不支持，不伪造相同 checkpoint。

B0 执行原 submit；B2/B3 取消原 submit，核验推荐由共同执行器落实，再由普通 H_base actor 至多四次调用继续，只有新提交提议才实际提交。推荐、落实、actor 最终提交分别存储。逻辑历史不重复加入物理重放动作，所有物理重放仍计成本。

在线调度函数不接收 raw task/gold，只有六字段公开 task projection 与图像资产。结束或停止之后才读取原任务评分字段，标签不参与调度、触发、重放或改选。

## 工件与成本

`progress.json` 从启动前保留全部计划配置；`online/` 保存完整请求、响应、截图、前后状态、动作回执、真正 checkpoint、核验与续跑。`api_wire/` 保存不含鉴权头的序列化请求、响应、逐次路由和保守支出预留。

`evaluator/CASE_TABLE` 和 `SUMMARY.json` 只在停止在线调用后生成，保留到 hook 覆盖、错误 checkpoint、正确状态损害、策略状态、核验是否实际执行与 crop 数。零错误 checkpoint 的恢复率为 N/A。主决策完成不是原 companion portal 的完整 benchmark 完成。

失败核验单列 `verification_call_attempts` 与 `verification_policy_returned`：已有调用尝试但尚未返回策略结果不能说未运行核验。计数中的尝试包含传输/费用边界失败，不自动等同真实远端 HTTP 派发，后者以 API wire / 支出记录为据。原 `score` 保留真实回执的原数据集判断；`confirmed_correct_completion` 另要求执行回执成功且看到确认页。收到正确选项的 POST、但确认完成未知，不计为已确认恢复。

两本账：

1. 实验实际支出：共享前缀仅计一次，控制、失败和全部物理重放都计入。
2. 单策略独立部署成本：每条策略均计入其共享前缀模型调用和已报告 token；不加实验为分叉而做的物理 reset/replay。

失败/缺失 usage 不算零 token；总 token 为已报告部分，并另列缺失记录数。API 预留不是实际账单。未证实网关计费基准时，不宣称可以按官方价格保证金额封顶。

正式启动目录必须是新目录；保存源文件副本、原清单副本、当次配置与运行元信息。不回写旧 manifest/score，不给旧结果追写当前代码身份。完成预定面板或遇到终止条件后停止，不自动扩展任务或开发机制。
