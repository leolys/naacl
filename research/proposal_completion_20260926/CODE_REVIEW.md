## 提案、展开与保留规则

- `propose` 的 raw/accepted 工件和 `result.proposals` 在任何 `expand` 调用前写盘；测试在 fake expand 实际进入时断言已持久化。
- 零提案合法，不是未运行。明确 `unexpanded` 保留完整原提案、具体原因和空链接；结构接口失败保留原始模型响应及错误，不尝试质量重跑。
- 不同提案产生同一行动标签，或展开改为另一合法选项，都不会被代码语义过滤。后者原链保留，`same_action_label`/`same_claim_text` 记录字面变化，不能被解释为语义保真。
- 初始链完整保留，新链只重命名 ID 防冲突；所有结构合法完整链一起进入核验。同 C 不去重，核验不佳不删除。
- 核验要求覆盖全部提供链 ID；字段、枚举、合法选项、引用关系检查属于结构校验，没有 Codex 按隐藏答案筛选。
- B 的含义、conditions 是否被静默增加或削弱、C 是否仍跟随原提案，需要独立离线逐项审阅。当前代码没有且不声称能自动证明这些语义性质。
- 如果全局预算/网络中止发生在展开期间，结果会保留已完成 proposal 和 expansions，但可能还没有最终 `candidate_set`。汇总时应从中止案例的 `result.json` 读取，不能因它未进入 summary.results 或缺少 candidate_set 而记成零提案/零输出。

1. **不是来源盲核验。** 核验没有接收完整 proposal、生成阶段的解释或检查结论，但新链 ID 仍有 `proposal_00_` 前缀，且旧链排列在前。不要称“核验器完全不知道哪条是新链”；本轮不需要为此扩展控制组。
