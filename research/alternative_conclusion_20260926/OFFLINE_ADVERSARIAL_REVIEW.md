# 其他结论先行：离线对抗审查

审查范围：仅阅读本地 v3 提示、三例报告、旧 online_defense 的 method.py / runner.py。未调用模型、SSH 或暂停中的 ARIS skills；未读取远端 pub001 运行工件。2026-09-26。

## 结论

用户的新方向与旧提示确实不同：旧问题的目标是找已有 O/B/C 的遗漏、条件与覆盖，新问题应搜索“图面还能引出什么不同的任务结论”。这是候选发现阶段，不是对旧链作否定裁决。可做固定 pub001 的有界开发诊断，但不能保证替代结论存在，也不能把暂时提出另一答案等同于纠错成功。

## 必须保留的边界

1. **另一结论是搜索假设，不是指定答案。** 不要求原结论错误，不按候选数量奖励，不循环假定“目标实体最大”然后把它当 B。允许搜索后无新增，记录具体检查范围。
2. **先假设 C 不等于编造 O。** 对候选回看图表，O 只能是可定位的图面记号、文字、空间关系；B 才写可见线索启发的解码假设。若图面没有相应依据，保留搜索失败，不编造观察完成链。
3. **已有覆盖可以结束。** 若初始已有该结论与依据，标为已覆盖；不必为反问凑出第三种答案。新的推导依据与新的 C 分开计数。
4. **严禁跨条件泄漏。** 在线只收到一个 arm 的图、公开任务、真实历史、候选；不能收到 clean/official 标签、gold、评分、人工指定区域或另一个 arm。模型看到的文件名与内部 metadata 也应审计。
5. **保留自然选择与提交。** 候选建议、actor 执行的选择、服务器真实提交分别记录。核验既不直接改选，也不确定性提交。
6. **不要搬旧提交护栏。** 旧 online_defense.action_support 要求 active 规则以及全部 supported 才允许选择/提交，且 schema 属于旧版。直接复用会把本轮改成另一种受控执行协议，并把未提交混入解释生成能力。
7. **已知失败开发例不是独立测试集。** pub001 是用户已有 clean 成功、official 失败的开发示例。只证明该例上的行为和可行性，不能泛化或计算基准胜率。
8. **没有重跑挑选。** 先固定任务、模型参数、提示与调用上限；模型仍失败照实报告。服务连接重试与质量重试区分。

## 推荐的通用反问草案

> 目标：扩展图表对当前公开任务可能支持的结论集合，不评价或反驳现有解释链。已有结论只用于避免重复，不是答案。
>
> 请重新看完整图表：除了当前集合已表达的任务结论，图面是否可能引出另一种具体结论——例如不同对象、比较方向、趋势类别或任务行动？从一个可能的不同结论出发，回看图中是否有可定位的记号、标签、位置、长度、颜色映射等足以构成其候选依据。
>
> 最多提出两个“其他结论”搜索问题；没有就返回空数组。问题应说明要搜索的具体结论及可检查的图面线索，不询问旧链是否错误、缺什么条件或哪种编码必然优先。不要预设必须有冲突或正确替代答案；不要虚构图面内容、任务规则或外部知识。
>
> 其他结论在此仅是待探索假设。后续阶段才把观察 O、明示解读规则 B、具体结论 C 组织成候选链，再交给独立核验。若图上没有形成候选的依据，明确记录未形成；若已经被现有集合覆盖，标记已覆盖，不复制链。

建议字段：question_id、candidate_conclusion、question、visible_search_cues、overlap_with_existing_conclusion_ids。这里的 visible_search_cues 只是检索位置/线索描述，不等同于已核验 O。若保留现有三问题预算，不必为本草案专门改限额。

### 后续补充提示的配套约束

> 回答这些其他结论搜索问题。对图面确有依据的候选，先列原样可见的 O，再明确 B 的解码与比较范围，最后表达具体 C。允许采用尚未核验的解读假设，但 B 不能只是把目标 C 换句话当作前提；不得增加图上没有的记号或任务中没有的政策。
>
> 可以返回新链、已覆盖或未形成。不要用“优先级不明”取代一个本可具体表达的条件性候选；同样不能因想得到另一答案而造链。保留所有原链，不在这里决定输赢。

## 对照与报告最低要求

- 优先固定同一公开状态、同一自然前缀和相同后续 actor 参数。若只对照旧部署结果，须显式列出参数/版本差异，不称严格方法因果对照。
- 只做“普通 agent 对比完整新流程”，结论只能是完整附加流程的开发效果，不能单独归因反问。若使用旧/新反问对照，应共享初始链、图像、公共历史、后续核验与 actor，避免同时换生成器或提交护栏。
- 原有官方 arm 名称只进入离线 manifest/scorer，不进入在线请求。真实提交后才离线评分。
- 报告分层：初始 C → 反问提出的 C 假设 → 实际形成新 OBC → 核验 → actor 首次选择 → 后续修改 → 最终提交与原评分。候选正确但最终未提交，不算恢复成功。
- 对 clean 同样运行/触发，才能看到额外探索是否把原本正确的决策改坏。
- 若新流程没有生成替代链，也是一条有效观察；不能反复调至 pub001 成功再称通用机制。

## 实施前尚需远端证据

远端旧 pair 的完整真实请求、动作回执、提交记录、scorer 结果，以及服务当前健康与冻结参数。此离线审查没有独立核实用户提供的服务与成绩摘要，不能作为这些事实的验证。
