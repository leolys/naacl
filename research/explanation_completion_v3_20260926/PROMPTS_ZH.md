# 本轮实际提示的中文阅读版

对应 `run_live_001/prompt_templates.json` 与冻结的 `prompts.py`。以下为 Codex 离线中文翻译与结构说明，不是另外发送给模型的提示。真实请求中的英文全文优先。不是为某个品牌、州或图表类别定制的提示。

## 共同规则

只使用所提供的完整图表、公开任务、真实公开历史和候选记录。输出简短、可核对的论证记录，不要求内部思维过程。候选、actor 提案和先前解释不是外部证据。印刷标签和通常的几何读法都没有自动优先级；不使用隐藏答案、底层数据、另一图表条件或先前核验裁决。

读法假设应由可见或公开线索引出。不得为凑成一条链虚构可见实体、数值、公开任务事实、业务规则、时间或唯一性要求。B 应提供条件性桥接，而不是换句话直接假定所需 C。这些限制不要求先证明读法适用。

- **O**：仅放定位明确的可见标记、原文和屏幕空间关系，例如颜色、位置、长度、附着关系、刻度、文字、打印数字。解码、语义映射与读法假设放在 B/conditions。
- **B**：说明如何在明示读法和条件下，由 O 推出与任务有关的 C。提出候选时不必先证实这些假设。
- **C**：一个具体、可检验的任务候选，可以是实体、比较、方向、有范围的结论或支持／拒绝某项行动；之后可能被证明错误。直接用自然语言写结论，不将所有 C 变为针对统一命题的二元标签，也没有 claim_kind 字段。
- **选项绑定**：仅当候选明确支持一个公开选项时，option_label 才填其原文，否则为 null。否定或比较结论可以没有选项；null 不代表“不确定”。

图像证据用 chart_1、可见位置和观察内容引用。公开任务证据单独用 public_task、给定的精确 JSON Pointer 和公开值引用；不能当成图像观察。保留已有 ID 和原文。补充必须关联实际问题和目标，顺序和重复不会增加证据权重。

若提供 decision_reference，它是公开目标和 actor 实际提议的选项，不是答案；不能强迫所有结论围绕同一个命题。可记录候选与该提案的支持、反驳、替代或无直接关系。没有该引用时不加这个字段。

## 1．初始生成

审查完整图和公开任务，表达它们可引出的读法。最多三条有区别的候选，不为凑数而生成；一至两条也可以，不同候选可以一致或竞争。可以采用尚未核实的 B/conditions 假设，但应同时明确该假设及其具体 C。生成与核验分开。

每条链必须以具体任务结论结束。缺少映射、比较不清、证据不足、无法决定或“不确定”都不作为 C。确实尚不能形成候选的问题，写在链外 unresolved_questions，说明具体问题及原因。若完全无法形成完整候选，返回空 rules/chains 和至少一个真实的链外问题，不虚构占位链。候选非空时也允许保留链外问题。不单独生成未使用的规则。

实际输出字段为 rules、chains、unresolved_questions。rules 保存条件桥接与适用范围；chains 保存 observations、task_evidence、rule_id、option_label、claim。无链外问题时返回空数组。

## 2．反问检查遗漏

面向整个初始候选集合和完整图表，检查遗漏观察、规则条件和覆盖范围。最多三个问题，也允许零个。保留所有初始候选。一个有公开线索却尚未表示的读法，即使 B 尚未核实，也可能值得提问。

问题可以带来新证据、条件细化、新候选，也可以不增加任何内容。候选之间允许一致，不制造冲突，也不为增加数量而强制新增链。初始未解决问题是单独记录，不是候选链。问题应引用实际初始链，问题不是裁决；总结检查范围与局限，不声称已证明完备。

## 3．回应反问并补充

依据实际问题、全部初始集合、公开任务和图表回应。原记录逐字保留。最多新增两条链／规则、两个细化，不必用满。

细化用于补充证据或说明已有条件；新候选应提供有实质不同的 O—B—C 依据，C 可以与原链相同。B 可以是有公开线索引出的、尚未测试的读法假设，不必先证明适用性才写出具体 C。

新链必须有具体 C。仍无法形成候选的情况放到链外问题处理结果，不生成“缺口链”。初始 unresolved_questions 原样保留。

输出 new_rules、new_chains、refinements、question_responses。每个问题恰有一个处理记录；新增链／细化与问题双向关联。若有新链，处理类型是 new_explanation；否则有细化则为 refined_existing；already_covered 引用相关初始链且不新增；unresolved 说明未解部分且不新增。无问题时四个数组均为空。不再允许 support_gap 关系或 claim_kind。

注意：本轮英文提示的 `record_ids`／`covered_chain_ids` 只给了空数组及一般关联说明，未把所有引用类型白名单都写明；代码更严格。pub013 暴露了这一接口说明不足。这里不事后改写冻结提示，也不修补旧响应冒充成功。

## 4．后续独立请求核验

逐条核验所提供候选，不改写 C，不选赢家。生成可能出错；按原样检查，保留分歧和不确定性。“独立”仅指同一模型发出的另一次请求，不是独立模型、严格盲审或人工确认。

每条链分别检查三个维度：

1. **O**：原文观察与公开绑定是否有图像／任务支持？解码后的排名、趋势、未打印的运算不是直接 O。打印数字是文字，不是独立证实的数据事实。
2. **B_applicability**：当前图与任务是否支持该解码及必要条件？明示读法尚未确立则记 undetermined；与证据相反则 refuted。一个合理的条件规则本身不足以判为适用。不得虚构政策、时间或唯一性要求。
3. **conditional_inference**：假定该链已经写明的 O、B 和条件，具体 C 是否能推出？能推出为 valid；逻辑、比较或范围错误为 invalid；缺少写明到足以检验的必要前提则为 incomplete，并列出缺项。**已写明的假设尚未证实，属于 B 适用性问题，不因此判条件推导缺前提。** 存在竞争读法或观察被否定，本身不推翻一个条件推导；也不能利用矛盾前提任意推出结论。

不能推出命题，不代表推出其否定；否定某对象为最大，不代表已找出另一个全局最大。不能默默引入其他链的比较或未声明的规则。不同选项不自动表示相互反驳，还需对应排他范围。若 C 实际只写了缺口而无具体候选，在推导检查中指出问题，不替换原文。

只引用该链及所用规则的真实前提 ID。细化没有独立 C，另行检查其新增证据／条件说明，不静默改写目标规则。链外初始问题不是待核验命题。

每条链和细化各覆盖一次；确定的支持／否定需有真实证据引用。valid／invalid 引用两项关联前提；incomplete 列明确缺项。不得为表示核验不确定而把 C 改为“不确定”。核验本身仍可能出错，不授权行动或提交。
