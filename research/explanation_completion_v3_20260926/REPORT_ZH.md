## 改了什么

新增独立目录 `explanation_completion_v3_20260926`，未覆盖旧 v1/v2、原任务、图表、答案或旧实验。

1. 初始生成和补充生成都要求 C 写具体候选；候选可以错误，不先证明 B 适用才允许提出。
2. 移除 claim_kind 与 support_gap 作为新链类型。不能形成候选的问题单列在链外，不把“证据不足”包装成 C。不强制统一是／否命题。
3. O 只记录可见文字、标记与空间关系。B 写读法和条件，不能把预期结论直接循环写成假设；不虚构图面或公开任务事实。
4. 反问检查整个初始集合，允许新候选、细化、已有覆盖或未解决，不强迫竞争或增加数量。
5. 后续分别核验 O、B 在当前任务中的适用性、给定明示前提的条件推导；核验不能反写原 C。
6. 保存未改写的链、核验状态和任务／图像范围限定的规则状态，写入后重读比对。本轮未接入后续业务 actor，未验证持久规则能改善行动。

结构校验只核对字段、引用、数量、关联和版本；不证明自然语言候选具体、正确、无循环或覆盖充分。提示要求也不是模型行为保证。

## 逐例解释

### b001：条件推导与适用性已经分开，但补链仍不足

初始 O 是饼图标题与 Apple45%、Xiaomi30%、Samsung15%、Others10% 四个印刷标签。B 明示采用文字作为份额值及最高份额选择规则；C 是选择 Apple。反问发现面积与标签不一致，询问是否指定标签优先，补充只增加了“Others 的扇区面积大于 Apple”的观察和条件说明。

后续核验给出 O 有支持、B 适用性未定、条件推导有效；C 逐字保留。规则 r1 为 pending，候选为 conditional_candidate。这里“不确定”指读法是否适用，而非把候选 C 改为无法决定。

**残余问题**：反问仍停在优先级／适用条件，没有把几何依据表述为另一条具体 O—B—C。允许零新增不是本例覆盖充分的证明。

旧记录的初始 Apple C 本来就具体，不应声称旧版只会生成不确定 C。旧核验把冲突问题记为 implication 不确定；本轮不同核验定义将其分配到 B 适用性。新旧生成与核验提示不止一处变化，只能描述历史差别，不能归因某一句 prompt 带来提升。

### b002：错误或不完整候选可以保留给核验

按印刷百分比读法，Edge87 大于 Chrome5、Safari1、Firefox23、Others3，因此初始生成 Edge 候选。另一条以共同基线柱高为读法，C 选择 Firefox，但它的 O 只明确记录 Firefox 高于 Edge。

反问没有增加第三条链，只给两个原链补充“缺少明确的指标标签／图例说明”的条件。核验认为两条 O 有支持、两种读法适用性都未定；Edge 条件推导有效；Firefox 推导 incomplete，因为原链未列出高于其余所有柱的前提。

这是将生成与核验分开的实际例子：保留“Firefox 最高”的具体主张，后续指出其论证缺项，不将其偷换成不确定或否定。incomplete 不是判 Firefox 事实错误，更不是判 Edge 为正确答案。两候选来自初始生成，不是反问的新增收益。

### pub013：初始观察与解读分开，补充接口没有跑完

初始 O 记录 IL 浅黄、KS 深酒红、DE 橙，以及色条浅黄端 High100、深色端 Low0。B 才采用“颜色按色条编码风险”的映射，C 选择三可选州中的 Illinois。没有在 O 直接写“IL 风险最高”。

反问问的是比较地图上所有州，还是只比较三个可选州。补充草稿采用“表单可选路由界定比较集合”的读法，再次得到 Illinois，标为 compatible；不是强制生成反对答案。

实际拒收原因：question_responses.record_ids 包含规则 ID `supp_r1`，校验要求该字段引用新增链／细化；另外 covered_chain_ids 填了新增 `supp_c1`，校验要求引用初始链。运行日志只报先遇到的前一种错误。

**归因边界**：冻结提示没有把这些 ID 字段的全部允许类型写明，接口要求比输出示例更细。因此不能只归咎于模型推理或图表能力。草稿仍保留供审查；未修改 JSON 使其通过、未追补核验、未声称完成持久化。
