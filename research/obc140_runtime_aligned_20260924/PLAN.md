# 原网页公开输入对齐修复

执行依据：用户在确认旧 OBC 投影绕过原网页中性化后要求“开始做”。本轮先修复输入、验证边界、提供可阅览的新版本并确定重跑范围。不得覆盖原图、原始任务、gold、旧请求或旧结果。

## 范围

- 固定原 140 个任务的 official140 图表；不选取成功样本，不扩展 clean 条件。
- 公开输入从已经归档的原网页非 review 模式入口、看板、表单 HTML 提取；不从原 spec.workflow_instruction 或含评分字段的 RUNTIME_TASKS 条目直接投影。
- 标题、任务目标、看板说明、公开规则表、表单选项顺序、字段及默认值、真实提交按钮取自可见 DOM。隐藏 input、评分元数据、脚本、数据文件、另一条件均不进入模型上下文。
- 公开业务阈值与任务对象不能为了“中性”被删除。网页本身仍有的证据通道指导独立标记，不悄悄重写任务，也不声称所有样本都已完全无提示。
- 这是新的静态图表解释输入协议，不是网页 Agent 执行轨迹。三个页面文字的可见内容可以作为一次性静态上下文；没有历史动作，没有真实提交。
- 保持已有 proposal / OBC generation / verification 提示和结构校验，不针对样本调整。新输入变更时禁止复用旧模型解释或规则状态。
- 中文仅用于独立阅览，不回流到英文模型输入。新展示明确写“修复后输入，解释未重新生成”。

## 工程工作与停止点

1. 实现新的 DOM 投影与每字段来源；比对 140 条旧输入并产出重跑清单。
2. 运行离线全量校验、必要 mock 回归与独立同家族审查，逐项保留发现和修正。
3. 输出单文件中文阅览、英文输入、未发送的请求预览、配置、命令和报告。
4. 本轮准备默认不发送 API。旧 20 美元上限对应已完成旧批次，不能静默重置后再次花费；准备好新范围/估算后申请明确的新预算，再启用真实调用。

不训练、不用 GPU、不连接远程运行任务，不改既有研究契约（工作区现有契约属于其他课题）。所有审查为同家族独立上下文的 provisional 工程审查，不冒充人工确认。
